# 08 总题干：Agent 的 RAG 遇到 PDF 应该怎么处理？

## 一、面试题原题

> **面试官问：** Agent 的 RAG 遇到 PDF 应该怎么处理？
>
> **换个问法：** 做 RAG 系统时，用户上传了一堆 PDF（合同/财报/论文/扫描件），你怎么处理才能让检索效果靠谱、回答不胡说、还能溯源？

---

## 二、通俗理解（先搞懂 PDF 为什么是个坑）

普通文本（.txt、.md）做 RAG 很简单：直接切片、向量化就行。但 PDF 之所以是面试高频题，是因为它 **"看起来是文本，其实根本不是纯文本"**：

| PDF 的坑 | 对 RAG 的破坏 |
|---------|--------------|
| 📄 扫描件 PDF（图片型） | 里面压根没文字，传统 RAG 读到的全是空的，白做 |
| 📊 表格 / 图表占了一半 | PDF 很多信息在表格和图里，纯文本提取会直接把表格切成一堆乱码 |
| 📑 格式极其复杂 | 页眉页脚、脚注、跨页表格、多级标题……切片时结构全丢，检索回来上下文全错 |
| 🔍 回答要溯源 | 用户问"这条合同条款在第几页第几章"，你不能答了就完，要能定位回去 |
| 📚 原生 PDF vs 扫描件混在一起 | 用户一次传的 PDF 可能类型不同，不能一刀切处理 |

**一句话：** PDF 做 RAG 的核心不是"切片+向量化"，而是 **"在切片之前，把 PDF 里的结构化信息 100% 抢救回来"**。
