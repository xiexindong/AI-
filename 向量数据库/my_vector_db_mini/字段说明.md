# my_vector_db_mini 目录 · 字段说明

这是 `ToyVectorDB.save_local(...)` 在磁盘上写出来的持久化文件。
跑 `python 示例.py mini` 后生成,里面有 **2 个 JSON 文件**,合起来就是一个完整的「向量数据库」快照。

> ⚠️ JSON 文件本身不支持注释(加 `//` 会导致 `json.load` 解析失败),所以本说明放到独立的 `.md` 里,作为「读这两个文件的字典」。

---

## 一、两个文件的总览

```
my_vector_db_mini/
├── db_meta.json   ← 【数据层】向量 + 原文 + 元信息 + 头信息
├── index.json     ← 【索引层】Flat 索引或 IVF 聚类信息
└── 字段说明.md    ← 就是本文件(人工讲解)
```

类比真实产品(Chroma):
- `db_meta.json` ≈ `chroma.sqlite3` + `data_level_0.bin`(存数据 + 向量)
- `index.json`   ≈ `index.html`(存 HNSW/Flat 索引结构)

## 二、db_meta.json 字段详解

### 字段总览

```json
{
  "dim": 48,                    // 向量维度(每个 chunk 变成几个浮点数)
  "embedding_model_name": "fake-embed-v1",  // 建库时用的 Embedding 模型名
  "index_type": "flat",         // 索引类型:flat 或 ivf
  "n_rows": 3,                  // 总记录条数
  "row_ids": [...],             // 每条记录的用户 ID
  "vectors": [...],             // 每条记录的 48 维向量(核心数据)
  "texts": [...],               // 每条记录的原始文本(查询返回时给用户看)
  "metas": [...]                // 每条记录的 metadata(来源/页码等)
}
```

### 逐字段说明

| 字段 | 类型 | 示例值 | 含义 |
|---|---|---|---|
| `dim` | int | `48` | 每条向量多少维。建库时 `ToyVectorDB(dim=48)` 决定,以后所有向量长度必须等于这个值 |
| `embedding_model_name` | string | `"fake-embed-v1"` | 建库时用的 Embedding 模型名。`load_local` 时会校验它和当前传入的模型是否一致,不一致直接报错,防止「建库 bge 查询 MiniLM」把结果搞乱 |
| `index_type` | string | `"flat"` / `"ivf"` | 当前库用什么索引。决定 `index.json` 里存的是 Flat 格式还是 IVF 格式 |
| `n_rows` | int | `3` | 库里现在有多少条记录 |
| `row_ids` | list[str] | `["id_001","id_002","id_003"]` | 每条记录用户给的外部 ID(对应 texts/vectors/metas 同位置) |
| `vectors` | list[list[float]] | `[[-0.041,-0.218,...], [...], [...]]` | **整个向量库的核心**。N×D 的浮点数大数组,每行 48 个数代表一条记录的语义指纹 |
| `texts` | list[str] | `["员工请假需提前...","报销需上传...","出差..."]` | 每条向量对应的原始文本(查询返回时给 LLM 或用户看) |
| `metas` | list[dict] | `[{"source":"员工手册.pdf","page":8,"tag":"请假"}, ...]` | 每条记录的元信息(谁给的、第几页、什么主题),搜索结果一起返回 |

### 关键设计:4 个列表是「平行数组」

`row_ids` / `vectors` / `texts` / `metas` 这 4 个列表**长度相同、位置一一对应**:

```
位置 0:  row_ids[0]="id_001"   vectors[0]=[0.04,...]   texts[0]="员工请假..."   metas[0]={tag:"请假"}
位置 1:  row_ids[1]="id_002"   vectors[1]=[0.21,...]   texts[1]="报销需上传..." metas[1]={tag:"报销"}
位置 2:  row_ids[2]="id_003"   vectors[2]=[0.11,...]   texts[2]="出差一线城市..." metas[2]={tag:"出差"}
```

搜索到第 5 个最相似的,就从 `row_ids[4]`、`texts[4]`、`metas[4]` 里取就行。

### 关键设计:`vectors` 存浮点数,小数点超长怎么办?

JSON 里 float 没有精度限制,Python 默认 `repr` 出来很长。真实产品(FAISS/Chroma)存的是 **float32 二进制**,不是 JSON,文件会小 4 倍以上。这里用 JSON 是为了让你**能直接用编辑器打开看清楚**。

## 三、index.json 字段详解(Flat 索引版)

```json
{
  "type": "flat",                // 索引类型标识
  "dim": 48,                     // 维度(冗余存一份,加载时做防御性校验)
  "vectors": [...]               // Flat 索引把所有向量又存了一份
}
```

### 为什么 Flat 索引又存了一遍 `vectors`?

因为 FlatIndex 类内部就是用一个 list 装所有向量做暴力检索。`db_meta.json` 和 `index.json` 各存了一份,内容完全一样。

> 真实 FAISS 的 `IndexFlatIP` 也是这样:索引文件里直接堆了一份向量数组。

## 四、index.json 字段详解(IVF 索引版,如果你跑 `full` 或 `cmp` 会看到)

跑 `python 示例.py full` 会生成 `my_vector_db/index.json`,里面是 IVF 格式:

```json
{
  "type": "ivf",
  "dim": 48,
  "nlist": 12,                   // 聚类桶数(把所有向量分成 12 个主题桶)
  "nprobe": 3,                   // 查询时扫几个桶(速度↔召回的旋钮)
  "centroids": [                 // 12 个桶的"代表向量"
    [48个浮点数],   // 第 0 个桶的代表
    [48个浮点数],   // 第 1 个桶的代表
    ...
  ],
  "buckets": [                   // 12 个桶,每个桶里是「row 编号列表」(不是向量,只是编号)
    [0, 5, 12, 88, 90],          // 桶 0 里有哪些 row
    [1, 2, 7],                   // 桶 1 里有哪些 row
    ...
  ]
}
```

| 字段 | 含义 |
|---|---|
| `nlist` | 把向量分成几个桶。等于"图书馆分几个书架" |
| `nprobe` | 查询时去几个最近的桶里找。等于"找书去几个书架翻" |
| `centroids` | 每个桶的「代表向量」(K-Means 算出来的中心)。查询时先拿 q_vec 和这 12 个代表比,选最近的 nprobe 个 |
| `buckets` | 每个桶装了哪些 row 编号(引用 db_meta.vectors 里的位置)。**注意:IVF 索引不重复存 vectors**,从 db_meta 拿 |

## 五、load_local 加载时的步骤(对应 [示例.py](file:///e:/workspace/面试总结/AI%20Agent%20面试题/向量数据库/示例.py) 的 [load_local](file:///e:/workspace/面试总结/AI%20Agent%20面试题/向量数据库/示例.py#L477-L519))

1. **读 db_meta.json**
   - 校验 `embedding_model_name` 和传入的 `expected_embedding_model` 一致 → 不一致报错
   - 把 `dim` / `row_ids` / `vectors` / `texts` / `metas` / `index_type` 填回新对象
2. **读 index.json**
   - 看 `type` 是 `flat` 还是 `ivf`,分别调 `FlatIndex.from_state()` 或 `IVFIndex.from_state()` 重建索引对象
3. **设置全局 `_GLOBAL_VECTORS`**
   - IVF 索引在 `search` 时需要访问所有向量,所以把 `db.vectors` 赋给模块级全局变量

## 六、用记事本 / VSCode 打开看的小技巧

1. **VSCode 直接打开**:格式化快捷键 `Shift+Alt+F`,JSON 自动缩进对齐,看着舒服
2. **想看 vectors 里的内容**:别逐位读浮点数,看前 4 位符号正负大致判断方向即可
3. **想验证一致性**:`db_meta.json.vectors[0]` 应该和 `index.json.vectors[0]` 完全一致(Flat 索引)
4. **删掉重建**:把整个 `my_vector_db_mini/` 目录删掉,再跑 `python 示例.py mini` 会重新生成

## 七、一句话回答「这两个文件到底存了啥?」

> `db_meta.json` = **数据**:「这些向量是哪几条数据的、原文本是什么、来源是哪一页」
> `index.json`   = **加速结构**:Flat 索引简单地把向量再存一份;IVF 索引存「聚类中心 + 哪条向量归哪个桶」的倒排表
>
> 两者合起来就是一个完整的、可独立启动的向量数据库——下次不用再算 embedding,直接 `load_local` 拿来用就行。
