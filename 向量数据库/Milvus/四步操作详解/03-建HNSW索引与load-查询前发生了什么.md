# 03 · 建 HNSW 索引与 load —— 查询前发生了什么

> 对应 [示例.py](../示例.py) 的 **Step 2.3 + Step 4**。回答的问题:「为什么建索引?为什么查询前还要 load?」

---

## 一、一句话理解

两个动作解决两个问题:

- **建索引** = 给数据做「目录」,查询从 O(N) 暴力降到 O(log N);
- **load** = 把目录和数据**搬进查询节点的内存**,让查询全程不读磁盘。

一句话串起来:**索引解决「算得快」,load 解决「取得到」**。

---

## 二、代码回顾

```python
# 建索引:定义在 Schema 之外,建表时一并提交
index_params = client.prepare_index_params()
index_params.add_index(
    field_name="vector",
    index_type="HNSW",                          # 分层小世界图
    metric_type="COSINE",                       # 余弦相似度
    params={"M": 32, "efConstruction": 200},
)

# load:把 Collection 加载进内存(查询前的必要条件)
client.load_collection(COLLECTION)
```

## 三、索引是怎么建的(内部流程)

```
数据攒满 → Segment 被 Seal(封段,见 02)
   │
   ▼
IndexCoord(协调器)下发建索引任务
   │
   ▼
IndexNode 从对象存储拉取这个段
   │
   ▼
逐点插入 HNSW 图:每个点找 M 个近邻连边,
按概率(1/M)决定是否提升到高层 → 形成分层小世界图
   │
   ▼
索引文件写回对象存储,QueryCoord 通知 QueryNode 加载
```

三个关键认知:

1. **异步**:建索引不阻塞写入,insert 早返回了,索引在后台慢慢建;
2. **切换**:Growing 段没索引也能查(暴力);索引建好自动切换走索引,查询无感提速;
3. **逐段**:索引是「一个段一份」,不是全表一份。

---

## 四、load 是怎么回事(为什么 Milvus 特色)

Milvus 是**存算分离**架构,数据和计算不在一台机器上:

```
磁盘(对象存储 MinIO/S3):持久的、便宜的、慢的   ← 数据住这里
内存(QueryNode):易失的、贵的、快的             ← 查询跑在这里

load = QueryNode 把 Sealed 段的「向量 + HNSW 索引」拉进自己内存
```

通俗类比:书都在图书馆书架上(对象存储),考试前把要考的几本复印一份放桌上(内存)——**翻书快了,但桌子(内存)有限,只放要考的书**。

所以:

- 查询是**内存级**速度,这是 Milvus 快的架构层原因;
- 内存不够 → load 失败或部分加载 → 生产要监控 QueryNode 内存水位;
- 没有目录的 Growing 段不用 load 概念,它本来就在内存里。

## 五、HNSW 参数回顾(追问必背)

| 参数 | 作用 | 什么时候调 |
|---|---|---|
| `M=32` | 每个节点的最大邻居数 | 越大召回越高、内存越大,默认不动 |
| `efConstruction=200` | 建图时候选队列长度 | 建库前定,影响索引质量,**建完不能改** |
| `efSearch=64~128` | 查询时候选队列长度 | **在线可调**:调大换召回,调小换速度 |

只有 efSearch 是「运行时旋钮」,前两个动它就要重建索引。

---

## 六、没 load 会怎样(高频坑)

```
search 一个没 load 的 Collection
  → 报错:collection not loaded
```

另一个坑:**删除大量数据后**,QueryNode 内存里的旧数据不会立刻消失,要 `release` 再 `load`(或等 compact)才真正释放——面试说得出这个,是有实操经验的信号。

---

## 七、面试要点(背这段)

> Milvus 存算分离:数据持久化在对象存储,查询跑在 QueryNode 内存。建索引是 IndexNode 对每个 Sealed 段异步构建 HNSW(不阻塞写入,建好自动切换);load 是把段的向量+索引进 QueryNode 内存,所以查询是内存级速度。HNSW 三参数:M=32 邻居数、efConstruction=200 建图质量、efSearch 在线可调的召回/速度旋钮。

---

## 八、常见追问

**Q1:索引和 load 有什么区别?(概念题,别答混)**
索引是「数据组织方式」,存在磁盘上,决定算多快;load 是「数据摆放位置」,决定查询节点能不能看到它。没有索引可以查(暴力),没有 load 一定查不了。

**Q2:亿级数据内存装不下怎么办?**
三个方向:按 Partition 分区按需 load、上 DiskANN(索引放磁盘)、用 IVF_SQ8/PQ 压缩向量减内存。企业里通常是分区 + 资源组按业务隔离。

**Q3:为什么 Growing 段没有索引也能查?**
它在内存里,直接暴力算距离,数据量小(还没攒满封段),慢一点无所谓。这保证了写入后毫秒级可查。
