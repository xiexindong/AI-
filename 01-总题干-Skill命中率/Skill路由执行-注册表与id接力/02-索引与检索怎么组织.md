## 一、向量索引:id 和向量互相对应

```
vector_index (存于向量数据库:FAISS / Milvus / Chroma)
┌─────────────────────────────────────────────┐
│ skill_id               embedding(1536维)      │
│ table-page-generator   [0.12, 0.88, ...]     │
│ form-page-generator    [0.45, 0.02, ...]     │
│ chart-page-generator   [0.71, 0.33, ...]     │
└─────────────────────────────────────────────┘
```

**两种操作:**
- **写(启动时)**:遍历注册表,对每条 `description` 做 embedding → `{id, vector}` 入库;
- **查(运行时)**:用户输入 embedding 成 `query_vec` → 算余弦相似度 → 返回 `[{id, score}...]` topK。

**关键:检索发生在索引上,检索结果直接是 id,不用碰文件。**

---

## 二、双索引结构:向量为主,关键词为辅

| 索引 | 类型 | 回答的问题 | 什么时候命中 |
|---|---|---|---|
| 向量索引 | 语义(embedding) | "意思像不像?" | 用户没说关键词,但意思接近 |
| 关键词索引 | 倒排表 `词 → [skill_id...]` | "有没有同一个词?" | 用户直说了"表格/PPT"这类词 |

**组织方式:**
- 关键词索引启动时从 description 里分词建好;
- 检索时两路并行,结果**合并 + 去重 + 分数加权**。

---

## 三、召回返回的数据结构(给精排层)

```json
[
  { "id": "table-page-generator", "score": 0.92, "source": "vector" },
  { "id": "form-page-generator",  "score": 0.48, "source": "vector" },
  { "id": "chart-page-generator", "score": 0.40, "source": "keyword" }
]
```

> 注意:召回层**只给 id 和分数,不给路径**——路径在注册表里锁着。

---

## 四、小节记忆

> 索引层:向量库管"语义像不像",倒排表管"有没有同词";
> 召回结果 = `[{id, score}]`,只定位不读文件。
