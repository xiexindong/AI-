# 01 文件与注册表怎么组织

>
> 本文件回答:**Skill 文件怎么摆?注册表里存什么、怎么查?**

---

## 一、Skill 仓库的目录结构:一个 Skill 一个文件夹

```
skills/                          ← 所有 Skill 的根目录
├── table-page-generator/
│   ├── SKILL.md                 ← 必备:定义(名字/描述/禁忌/参数)
│   ├── templates/               ← 可选:模板文件
│   │   ├── DataTable.tsx
│   │   └── user-list.example.tsx
│   └── scripts/                 ← 可选:可执行脚本
│
├── form-page-generator/
│   ├── SKILL.md
│   └── templates/
│
└── manifest.json                ← 可选:手写清单(加速启动,免扫描)
```

**组织规则:**
- 文件夹名 = Skill id(全系统唯一);
- 每个 Skill 必须带一个 `SKILL.md`;
- 格式统一 → 启动时一套解析器批量注册,不用为每个 Skill 单独写代码。

---

## 二、SKILL.md 的 frontmatter(注册表的数据来源)

```yaml
---
name: table-page-generator            # ① id:全系统唯一的"名字",路由只认它
description: >                         # ② 正面描述:写"何时用"+触发词,决定召回命中
  当用户需要后台列表/表格页面时使用。触发词:表格页、列表页、分页、筛选...
negative_description: >                # ③ 负面描述:写"何时别用",做边界防御
  不要用于表单页、详情页、图表页。
version: 1.0.0                         # ④ 元信息
entry: SKILL.md                        # ⑤ 入口文件(默认就是 SKILL.md)
---
```

---

## 三、注册表的数据结构:一张 Map

```ts
type SkillId = string

interface SkillMeta {
  id: string                 // = name,唯一
  description: string        // 正面描述(召回/精排都要用)
  negativeDescription?: string  // 负面描述(精排时排除)
  path: string               // 相对根目录的路径(执行时用)
  version?: string
  entry?: string             // 入口文件,默认 'SKILL.md'
}

const registry = new Map<SkillId, SkillMeta>()
```

---

## 四、为什么是 Map 而不是数组?

| 组织方式 | 查找复杂度 | 说明 |
|---|---|---|
| 数组(遍历) | O(n) | Skill 多了就慢 |
| **Map(哈希)** | **O(1)** | LLM 输出 id → 一行 `registry.get(id)` 秒拿路径 |

---

## 五、注册表支持三种查询方向

| 查询方向 | 谁在用 | 干嘛 |
|---|---|---|
| `id → meta` | 执行引擎 | 拿 path,加载文件 |
| `id → description` | 路由(召回/精排) | 组 prompt、做检索 |
| `id → 全列表` | 路由策略选择 | Skill 少时全量塞 prompt |

---

## 六、小节记忆

> 文件层:一个 Skill = 一个文件夹 + 一个 SKILL.md(frontmatter 是唯一名片);
> 数据层:注册表 = `Map<id, SkillMeta>`,路径锁在表里,只认 id 查。
