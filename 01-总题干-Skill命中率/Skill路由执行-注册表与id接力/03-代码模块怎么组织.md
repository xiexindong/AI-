## 一、五个模块,单向依赖

```
src/
├── skill-loader/      ① 启动时:扫描目录 → 解析 frontmatter → 交给 registry
├── registry/          ② 注册表:唯一数据源,提供 id→meta 查询
├── vector-index/      ③ 索引:从 registry 读 description → embedding → 检索
├── router/            ④ 路由:召回(vector-index) + 精排(LLM) → 输出 id
└── executor/          ⑤ 执行:拿 id 查 registry 的 path → 加载 SKILL.md → 运行
```

**依赖关系(单向):**

```
① skill-loader ──写──→ ② registry
③ vector-index ──读──→ ② registry (description)
④ router ──召回──→ ③ vector-index
④ router ──读──→ ② registry (候选描述组 prompt)
④ router ──决策──→ LLM (外部)
⑤ executor ←──id── ④ router
⑤ executor ──查──→ ② registry (拿 path)
```

---

## 二、三条组织原则

| 原则 | 体现 | 好处 |
|---|---|---|
| **单一数据源** | 所有路径/描述只在 registry | 改一处,全系统生效 |
| **单向依赖** | loader→registry→router→executor | 不循环引用,好维护 |
| **id 是唯一契约** | 模块之间只传 id,不传文件 | 解耦 + 安全 |

---

## 三、数据流全图

```
文件系统 ──(loader)──→ 注册表 ──(索引)──→ 向量库
                                        │ 用户输入
                                        ▼
                                   router(召回+精排)
                                        │ {skill: id}
                                        ▼
                                  executor ──查──→ 注册表 ──→ 文件系统(加载执行)
```

---

## 四、小节记忆

> 模块层:loader 造表、registry 管表、index 检索、router 定 id、executor 执行;
> 传参只有 id,依赖只有一条链。
