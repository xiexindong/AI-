# Step 1 · 分析需求

目标:把用户的一句需求,拆成配置的四个部分。**先拆,再动手,禁止边写边想。**

## 拆解模板

| 配置部分 | 从用户的话里找什么 | 例子 |
|---|---|---|
| `title` | 管理对象的名字 | "订单管理"、"用户列表" |
| `api` | 数据来源接口(可能没明说 → 按 REST 惯例推断 `/<资源名>`) | "/orders" |
| `columns` | 每个"要展示/筛选/排序"的字段 | 订单号、创建时间、状态、金额 |
| `extra` | 批量操作、多选行、默认排序等附加能力 | 发货/关闭按钮 |

## 拆解清单(每条都要问)

1. 页面管什么数据?(→ title / api)
2. 用户提了哪些**要展示**的字段?(→ columns)
3. 哪些字段**要筛选**?筛什么方式?("按时间"→dateRange,"多选"→multiSelect)
4. 哪些字段**要排序**?(→ sortable)
5. 有没有**合计/统计**?(→ summary)
6. 有没有**批量操作/勾选行**?(→ extra.rowSelection + batchActions)
7. 有没有说**默认排序**?(→ extra.defaultSort)

## 输出格式(给 Step 2 的交接)

```json
{
  "title": "订单管理",
  "api": "/orders",
  "需求清单": ["按创建时间范围筛选", "状态多选筛选", "部门级联筛选", "金额排序+合计", "批量发货"],
  "不确定项": ["状态选项来源接口", "部门树接口"]
}
```

## 注意

- 用户没提到的字段,默认只展示核心 4~6 列,不要贪多;
- 接口路径不确定时,标注"不确定项"交给用户确认,不要瞎编;
- **禁止**在这里写任何代码,只输出拆解结果。
