# 01 总题干：Skill 数量一多，Agent 的命中率怎么保证？

## 一、面试题原题

> **问题：** Skill 数量一多，Agent 的命中率怎么保证？
>
> **换个问法：** 当 Agent 有几十上百个 Skill（工具/插件）时，怎么保证它不会"选错技能"？

---

## 二、通俗理解（先搞懂问题本质）

### 2.1 什么是"命中率"？

命中率 = Agent **选对 Skill 的次数** / **总调用次数**

| 场景 | 命中了？ | 说明 |
|------|---------|------|
| 用户说"帮我做个 PPT"，Agent 调了 `生成PPT` skill | ✅ 命中 | 选对了 |
| 用户说"帮我做个 PPT"，Agent 调了 `写文档` skill | ❌ 没命中 | 选错了，语义歧义 |
| 用户说"帮我做个 PPT"，Agent 说"我不会" | ❌ 漏召回 | 根本没找到能用的 skill |

### 2.2 为什么 Skill 一多，命中率就下降？

**打个比方：** 你去饭店吃饭，菜单只有 5 道菜，服务员一眼就能记住你点的啥；但如果菜单有 500 道菜，服务员很可能听错、记混。

Agent 选 Skill 的原理是 **语义匹配**（计算用户输入和每个 Skill 描述的"相似度"），问题出在：

1. **语义冲突**：两个 Skill 描述很像（比如"生成PPT"和"生成文档"），模型傻傻分不清楚
2. **描述太泛**：Skill 的 description 写得太笼统（"负责生成各种文件"），等于没写
3. **候选太多**：一次性塞给模型 100 个 Skill，上下文装不下，或者注意力分散
