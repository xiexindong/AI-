# 01 总题干：Skill 数量一多，Agent 的命中率怎么保证？

## 一、面试题原题

> **问题：** Skill 数量一多，Agent 的命中率怎么保证？
>
> **换个问法：** 当 Agent 有几十上百个 Skill（工具/插件）时，怎么保证它不会"选错技能"？

---

## 二、通俗理解（先搞懂问题本质）

### 2.1 什么是"命中率"？

命中率 = Agent **选对 Skill 的次数** / **总调用次数**

| 场景 | 命中了？ | 说明 |
|------|---------|------|
| 用户说"帮我做个 PPT"，Agent 调了 `生成PPT` skill | ✅ 命中 | 选对了 |
| 用户说"帮我做个 PPT"，Agent 调了 `写文档` skill | ❌ 没命中 | 选错了，语义歧义 |
| 用户说"帮我做个 PPT"，Agent 说"我不会" | ❌ 漏召回 | 根本没找到能用的 skill |

### 2.2 为什么 Skill 一多，命中率就下降？

**打个比方：** 你去饭店吃饭，菜单只有 5 道菜，服务员一眼就能记住你点的啥；但如果菜单有 500 道菜，服务员很可能听错、记混。

Agent 选 Skill 的原理是 **语义匹配**（计算用户输入和每个 Skill 描述的"相似度"），问题出在：

1. **语义冲突**：两个 Skill 描述很像（比如"生成PPT"和"生成文档"），模型傻傻分不清楚
2. **描述太泛**：Skill 的 description 写得太笼统（"负责生成各种文件"），等于没写
3. **候选太多**：一次性塞给模型 100 个 Skill，上下文装不下，或者注意力分散

---

### 2.3 一个完整例子：描述写得好不好，命中率差多少

**场景：** Agent 有 3 个 Skill，用户说"帮我做个 PPT"

```
候选 Skill:
  A. generate_ppt    生成PPT
  B. generate_doc    生成Word文档
  C. generate_chart  生成图表
```

**❌ 糟糕描述（写"是什么"）：**

```yaml
name: generate_ppt
description: "生成PPT文件的技能，支持创建演示文稿，可以添加幻灯片、设置主题、插入文字和图片，导出为.pptx格式"
```

- 问题：全在堆砌"我能干什么"，**没说"什么时候该用我"**
- "帮我做个 PPT" → 碰运气命中 ✅
- "帮我整理一份汇报材料" / "做个演示" → 相似度低 → **漏召回** ❌
- 如果 `generate_doc` 也写成"生成各种文件" → 两个 Skill 互相抢 → **语义冲突** ❌

**✅ 好描述（写"何时用" + "何时别用"）：**

```yaml
name: generate_ppt
description: >
  当用户想要"演示文稿、幻灯片、PPT、汇报材料、演讲/讲课的展示内容"时使用。
  触发词:做PPT、做个汇报、搞个演示、课程展示、产品发布材料、总结汇报。
  用途:根据主题生成结构化幻灯片(标题、大纲、要点页、演讲备注)。
  注意:如果用户只要文字文档(Word/报告/文章),用 generate_doc,不要用它。
```

```yaml
name: generate_doc
description: >
  当用户想要"Word 文档、文字报告、文章、说明书、合同、简历"时使用。
  触发词:写个文档、整理报告、出份合同、简历、总结成文字。
  注意:如果用户要的是演示幻灯片,用 generate_ppt,不要用它。
```

**命中对照表：**

| 用户输入 | 旧描述结果 | 新描述结果 |
|---|---|---|
| "帮我做个 PPT" | 碰运气命中 | ✅ 命中（触发词"PPT"） |
| "做个汇报材料" | ❌ 漏召回 | ✅ 命中（"汇报材料"+"演示文稿"） |
| "整理一份文字报告" | ❌ 可能错用 generate_ppt | ✅ 命中 generate_doc（负面描述挡开了） |
| "我讲课想投个屏" | ❌ 漏召回 | ✅ 命中（"讲课的展示内容"） |

**为什么新描述命中率高？**

```
旧描述回答："我是谁，我能干什么"   → 泛，匹配靠碰运气
新描述回答："什么情况下找我"       → 精准，把"触发场景"写进描述
            "什么情况下别找我"     → 负面描述，把歧义边界划清楚
```

> 面试一句话："保命中率的第一招是描述优化：写'何时用'（触发场景+触发词）而不是'是什么'（功能堆砌），再补'何时别用'做边界防御——用户输入千变万化，只有描述覆盖了触发场景，语义匹配才能稳定命中。"
