# 策略 01：描述优化 —— 写"何时用"，而非"是什么"

## 一、核心观点

> Name 和 Description 本质上是给 **Agent 路由用的检索摘要**，语义匹配依赖 **场景**。

---

## 二、❌ 错误方向：功能堆砌

新手常见写法——把 Skill 内部能干嘛全列出来：

```text
name: "ppt-generator"
description: "负责生成 PPT，排版，以及整理汇报材料。支持多种模板，自动分页，自动插入图表，可以导出为..."
```

### 问题在哪？

- 过度优化 Skill 内部的 Prompt，对外描述却干瘪
- Agent 靠"脑补"进行路由匹配，极易产生**语义歧义**
- 比如"整理汇报材料"和写 Word 文档的 Skill 描述撞车了

---

## 三、✅ 正确方向：聚焦触发场景

按 **Anthropic 官方建议**——直接告诉 Agent：**用户说什么话的时候，才用我这个 Skill**：

```text
name: "ppt-generator"
description: "当用户需要制作汇报材料、融资路演或季度总结时使用此技能。"
```

### 为什么这招管用？

| 对比维度 | 功能堆砌 ❌ | 场景描述 ✅ |
|---------|-----------|-----------|
| 匹配依据 | "这个 Skill 能做什么" | "用户说过类似的话没有" |
| 语义歧义 | 高（整理材料=PPT？Word？Excel？） | 低（"融资路演"≈铁定是 PPT） |
| 依赖模型想象力 | 高（需要 Agent 自己推理 PPT=路演） | 低（直接写死场景） |
| Skill 多了之后 | 互相打架 | 各管各的场景 |

> **金句记忆：** 模型路由本质是**语义距离匹配**，场景描述越具象，越不依赖 Agent 的泛化猜测。

---

## 四、进阶写法模板

```text
description: "当用户需要【具体场景A】、【具体场景B】或【具体场景C】时使用此技能。"
```

实战例子：
- 搜索 Skill：`"当用户需要查新闻、查实时信息、查不知道的知识时使用此技能。"`
- 代码 Skill：`"当用户需要写代码、改 Bug、调试程序时使用此技能。"`
- 画图 Skill：`"当用户需要生成图片、画头像、做海报时使用此技能。"`
