# 命中率背后的三大支柱（整体总结）

## 一、核心结论

> **功夫不仅在 Skill 本身，更在 Agent 的上下文工程。**

Skill 命中率不是靠调大模型参数解决的，本质是一个**工程问题**。

---

## 二、三大支柱总览

| 支柱 | 名称 | 核心要点 | 对应子策略 |
|------|------|---------|-----------|
| ① | **贴合业务的 Agent 底座** | 基于业务场景提供优质的上下文环境与推理框架——这是整个链路有效运作的**基础**。没有好的底座，后面全白搭。 | 整个 Agent 架构层（单独话题） |
| ② | **描述分层，带正负样例** | 构建清晰分层的架构树，在描述中不仅写"何时用"，必须加入防御性的**误报拦截案例**。 | = 策略 01（写"何时用"）<br>+ 策略 03（负面描述/边界防御） |
| ③ | **"召回+精排"的路由机制** | 针对规模膨胀问题，先用轻量手段缩小范围，再让大模型进行深度语义的精排判断。 | = 策略 04（召回+重排兜底） |

## 三、面试 3 句话版答案（直接背）

> **第一句（定调）：** Skill 命中率不是靠调大模型参数解决的，本质是一个**工程问题**，核心在"上下文工程"。
>
> **第二句（拆解）：** 我一般分三层做：第一层是**描述层**，Skill 写"何时用"不写"是什么"，再加负面描述画清边界；第二层是**路由层**，Skill 多了之后用"召回+精排"的两阶段流程，先 Embedding 捞 Top10 再让 LLM 精挑；第三层是**底座层**，整个 Agent 要有贴合业务的推理框架，不能让 LLM 在真空中瞎选。
>
> **第三句（举例子）：** 比如我们之前有 200 多个 Skill，全塞给 LLM 选错率有 40%，加上召回+精排之后直接降到 5% 以内，再加负面描述又降到 1% 左右。
