# 方案 4：Agent 工具链按需加载（第三步 · 新增）

## 一、解决什么问题？

> 前面 3 层（多模态解析 / 结构还原 / 语义切片）解决的都是"把 PDF 建好库"的问题。
> 但真正生产级的 PDF RAG，**用户的问题不会刚好匹配一个 chunk**。

举个面试常见场景：
> **用户问：** "对比一下这份财报里 2022 年和 2024 年的毛利率，做个简单的差异分析。"

| 做法 | 传统单步 RAG ❌ | Agent 工具链 ✅ |
|------|---------------|--------------|
| 怎么答 | 搜一个最像的 chunk → 让 LLM 直接编 | 让 Agent **按需调用多个工具联动**，一步一步解决 |
| 结果 | 大概率数字错（毛利率是计算出来的，原文不直接写），或者只算了一年的 | 抽两年数据 → 算毛利率 → 对比分析，结果全对 |

**一句话：** 简单问答靠 RAG 一次检索就够了，**跨表格、跨页、需要计算/画图的复杂问题，必须让 Agent 自己拆任务 + 调多个工具一步步跑**。

---

## 二、Agent 需要的 4 个核心工具（抽表 + 读页 + 看图 + 检索）

图里给了 4 个动作：**检索、读页、抽表、看图**。

```
用户问题
   ↓
Agent（规划要调用哪些工具，调几次）
   │
   ├─→ 🔍 工具1：检索（semantic_search）
   │      入参：用户问题 → 回：最相关的 Top N Chunk + 页码
   │
   ├─→ 📖 工具2：读整页（read_page）
   │      入参：doc_id + page_number → 回：该页完整结构化内容 + 页内所有图表
   │
   ├─→ 📊 工具3：抽表（extract_table）
   │      入参：doc_id + page_number + table_id → 回：JSON/Markdown 格式的完整表格（一行不漏）
   │
   └─→ 🖼️ 工具4：看图（analyze_chart）
          入参：doc_id + page_number + image_id → 回：多模态模型输出的图表解读摘要
```

### 4 个工具分别什么时候被 Agent 调？

| 用户问题里的信号 | Agent 会调哪个工具 | 为什么？ |
|---------------|----------------|---------|
| "有没有提到 XX？" | 检索（第 1 次，粗搜） | 快速定位相关 chunk 和页码 |
| "第 12 页具体怎么说的？" | 读整页（read_page） | 一个 chunk 太小，要整页上下文才靠谱 |
| "2024 年的各项费用分别是多少？" | 抽表（extract_table） | 表格内容不能靠检索片段，要完整抓出来再算 |
| "这个柱状图反映了什么趋势？" | 看图（analyze_chart） | 纯文本里根本没图的信息，必须单独调多模态 |

## 三、"按需加载"到底是什么意思？

**不是把 4 个工具全都一次性让 Agent 跑一遍，而是 Agent 自己判断：我现在需要什么就调什么。**

用上面那个"毛利率对比"的问题，演示一次真实调用链：

```
用户问：对比 2022 和 2024 年毛利率

Agent 思考 Step 1：先定位利润表在哪页
   → 调 🔍 检索："合并利润表 毛利率"
   → 拿到：表3-2 在第 34 页

Agent 思考 Step 2：需要完整的利润表才能算毛利率
   → 调 📊 抽表：doc_id=xxx, page=34, table_id="表3-2"
   → 拿到：2022 营收100/毛利25、2024 营收186/毛利55.8

Agent 思考 Step 3：计算毛利率并对比
   → LLM 自己算（不用调工具）：2022=25%，2024=30%，↑5 个点
   → 生成差异分析，并在每一个数字后标注（第34页 表3-2）
```

这就叫"按需加载"——Agent 自主规划工具调用顺序和次数，**而不是死板的"检索一次然后生成"**。

## 四、和"普通 RAG"的区别（面试加分项）

| 维度 | 普通 Demo 级 RAG | 生产级 Agent 工具链（本题答法） |
|------|----------------|------------------------------|
| 检索次数 | 1 次，命中啥算啥 | Agent 可决定多次检索、多次翻页 |
| 表格处理 | 靠检索片段，数字经常不完整 | 抽表工具直接拉完整表格，可跨表计算 |
| 图表处理 | 完全没招，看不到图 | 调看图工具，多模态直接解读 |
| 复杂问题 | 回答"像那么回事"但细节错 | 可以做计算、对比、汇总，结论真实可复核 |
| 面试官视角 | "跑过大模型 Demo" | **"真正理解 PDF RAG 生产级难点"** ✅（就是最后那张图里面试官评语的那句话） |

> **一句话记忆：** 前三层是给 Agent 准备好"弹药库"（建好索引），工具链按需加载是让 Agent **自己决定拿哪把枪、打几枪**——不会因为一次检索不全就瞎编，而是"不明白就再翻一页、再抽张表"。
