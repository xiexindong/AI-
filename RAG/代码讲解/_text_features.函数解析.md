# `_text_features` 函数解析:`strip` 等是什么意思、函数的目的

> 出处:`真实例子.py` 第 72~77 行。

```python
def _text_features(text: str) -> list[str]:
    """把文本拆成特征列表:所有单字 + 所有相邻双字"""
    features = [ch for ch in text if ch.strip()]
    features += [text[i:i+2] for i in range(len(text) - 1) if text[i:i+2].strip()]
    return features
```

---

## 一、函数的目的(一句话)

> **把一段文本拆成一堆"特征",供后面的 `_char_vec` 逐个生成向量**。特征是两类:所有单字 + 所有相邻双字(两个字挨在一起的组合)。

举例:

```python
_text_features("差旅报销")
# 单字:['差', '旅', '报', '销']
# 双字:['差旅', '旅报', '报销']
# 合并:['差', '旅', '报', '销', '差旅', '旅报', '报销']
```

它是"文本 → 向量"流水线的**第一道工序**:先拆特征,再让每个特征生成一个 64 维向量(`_char_vec`),最后累加成文本向量(`embed`)。

---

## 二、逐行拆解

### 第 74 行:单字特征

```python
features = [ch for ch in text if ch.strip()]
```

- `for ch in text`:遍历文本的每个字符
- `ch.strip()`:见下文第三节,作用是"判断 ch 是不是纯空白"
- `if` 过滤:空白字符不要,其余全部保留
- 结果:把所有**非空白单字**收进列表

### 第 75 行:相邻双字特征

```python
features += [text[i:i+2] for i in range(len(text) - 1) if text[i:i+2].strip()]
```

- `range(len(text) - 1)`:文本长 n 个字符,相邻双字有 **n-1** 个(每对相邻字符一个)
- `text[i:i+2]`:切片,取第 i 个字符和它右边一个,共 2 个字符
- `.strip()` + `if`:两个字符都是纯空白才不要(比如两个连续空格)
- `features += [...]`:把双字列表**追加**到单字列表后面(等价于 `features.extend(...)`)

### 第 76 行:返回

返回合并后的完整特征列表(单字在前,双字在后)。

## 三、里面的每个 Python 知识点

### 1. `str.strip()`——去掉字符串首尾空白

```python
"  报销  ".strip()   # → "报销"
"差旅".strip()        # → "差旅"(没有空白,原样返回)
"  ".strip()          # → ""(全是空白 → 空串)
"".strip()            # → ""
```

- 默认去除**首尾**的空白字符:空格、制表符 `\t`、换行 `\n`、回车 `\r` 等(含中文全角空格)
- 字符串不可变,所以它**返回新字符串**,原字符串不变
- 在这里它的角色不是"清理数据",而是**当判断条件用**:

```python
if ch.strip():      # 等价于 if ch 不是纯空白
```

空字符串在 Python 里是 **falsy**(条件判断为假),非空字符串是 truthy。所以 `"  ".strip()` 得 `""` → 条件为假 → 过滤掉。**空白字符对检索没有意义**,直接丢弃。

### 2. 列表推导式 + if 过滤

```python
[表达式 for 变量 in 可迭代对象 if 条件]
```

把循环 + 判断 + 收集压缩成一行。等价于:

```python
features = []
for ch in text:
    if ch.strip():
        features.append(ch)
```

### 3. 切片 `text[i:i+2]`

取字符串第 `i` 到第 `i+1` 个字符(左闭右开,含 i 不含 i+2):

```python
"差旅报销"[0:2]   # → "差旅"
"差旅报销"[1:3]   # → "旅报"
"差旅报销"[3:5]   # → "销"(越界自动截断到末尾)
```

### 4. `range(len(text) - 1)`——为什么是 n-1 个(完整推导)

#### ① 问题:n 个字,相邻双字有几个?

以"差旅报销"4 个字为例,把下标写出来:

```
下标:0   1   2   3
     差  旅  报  销
```

相邻对 = 每两个**挨在一起**的字符各成一个:

| 起始下标 i | 切片 `text[i:i+2]` | 得到 |
|---|---|---|
| 0 | `text[0:2]` | 差旅 |
| 1 | `text[1:3]` | 旅报 |
| 2 | `text[2:4]` | 报销 |
| 3 | `text[3:5]` | **销**(不是双字!)|

- 有效起始位置:0, 1, 2 → **n-1 个**(4-1=3)
- 下标 3 是最后一个字符,它右边**没有字符可以配对**了

```
差 旅 报 销
└┬┘└┬┘└┬┘
差旅 旅报 报销
```

**通用规律:n 个字符,相邻双字一定是 n-1 个**(每对相邻字符一个,最后一对从 n-2 开始)。

#### ② 为什么是 `range(len(text) - 1)` 而不是 `range(len(text))`

`range(n-1)` 生成 `0, 1, ..., n-2`,正好是上面的有效起始下标集合。

如果贪心写成 `range(len(text))`(即 0,1,2,3),i=3 时会发生什么?

```python
"差旅报销"[3:5]
```

Python 切片**越界自动截断**:`text[3:5]` 只有下标 3 一个字符,返回 `"销"`。

后果:
- `"销"` 只有 1 个字,不是"双字"特征,混进双字列表会破坏"双字代表词组"的语义
- 每个文本都会多出**最后一个字的单字特征**(重复特征,浪费计算,还可能在 IDF 统计里重复计数)

所以必须 `-1`,把最后一个"没得配对的字符"排除在外。

#### ③ 如果文本很短呢(边界情况)

| text | len | range(len-1) | 双字特征 |
|---|---|---|---|
| `"差旅报销"` | 4 | `range(3)` → 0,1,2 | 差旅、旅报、报销 |
| `"报销"` | 2 | `range(1)` → 0 | 报销 |
| `"报"` | 1 | `range(0)` → 空 | 无(1 个字凑不成双字,合理) |
| `""` | 0 | `range(-1)` → 空 | 无(空文本,合理) |

`range(0)` 和 `range(-1)` 都是空序列,天然安全,不会报错。

#### ④ 一句话记忆

> 相邻双字的数量 = **字符数 - 1**(最后一个字符右边没人配对);`range(len(text) - 1)` 就是精确给出"所有有效起始下标"的最短写法。

### 5. `features += [...]`——列表拼接

`+=` 对列表等价于 `extend`:把右边列表的元素逐个追加进去,原地修改 `features`。

## 五、为什么这样拆(单字 + 双字,在 RAG 里的意义)

### 1. 特征太细会怎样(只有单字)

如果只有单字,"报销"和"差旅"共享的字太少(共零个字),检索时"差旅报销"和"报销制度"只能靠单个字重合,区分度差。这是注释里说的**旧版 `示例.py` 的痛点**。

### 2. 双字特征解决了什么

把"差旅""报销""住宿"这些**有意义的整体词**当成一个特征:

- 文档里出现"差旅报销",拆出的双字里有"差旅""报销"
- 问题"打车费能报销吗",拆出的双字里有"报销"
- 双方共享特征"报销"→ 文本向量更接近 → 检索命中

这正是模拟**真实 embedding 模型的语义能力**:词(或子词)是整体进入向量空间的,而不是被拆成单字。

### 3. 单字 + 双字混合的好处

| | 单字 | 双字 |
|---|---|---|
| 覆盖 | 所有字,不漏 | 有语义的词组 |
| 问题 | 区分度低 | 覆盖不全(罕见组合没有) |
| 合起来 | 每个文本都有完整特征 | 关键词组成为"强特征" |

所以两者**互补**:单字保底不漏,双字提供语义区分度。

### 4. 空白字符为什么要过滤

空格、换行对语义没有贡献,如果保留它们:
- 单字列表里出现 `' '` 这种无意义特征
- 双字里出现 `"差 "`、`" 住"` 这种"夹带空白的伪词组",会把不同文本的特征搅乱

`if ch.strip()` 一行就把它们全部排除。

### 5. 大白话:这一切都是为了"检索匹配度"

用大白话把上面 4 点串起来:**这个函数拆出来的特征越"精准",检索时"问的问题"和"文档"就越容易对得上——这就是检索匹配度。**

打个比方,把"拆特征"想成"怎么向别人描述一样东西":

- **只拆单字,就像把"苹果手机"拆成"苹、果、手、机"**。描述太碎:你说"果",别人可能想到水果、结果、果然……什么都沾点边。检索时也一样:只按单字算相似度,问题"苹果怎么充电"和文档"水果店促销"都含"果",会被拉高相似度——匹配糊、噪音大,排在前面的文档经常不是你要的。
- **加上双字,就像说"苹果"两个字**。一下精准了:"苹果怎么充电"和"苹果手机说明书"共享整体特征"苹果",强特征直接对上。这就是注释里"双字让检索效果比纯单字好很多"的原因。
- **过滤空白,就像把话里的"嗯、啊、空格"去掉再说**。留着空格,会拆出"苹 果""果 手"这种带空格的怪词组,既不是词也看不懂,只会给相似度加噪音;去掉后,剩下的全是干净的有效特征。

所以整个函数的设计逻辑就一句话:

> **特征拆得准 → 相似度算得准 → Top-K 检索出来的就是真正相关的文档 → 匹配度提高。**

验证方式也很直观:看 `真实例子.py` 运行结果里每一问的 `score` 和命中的文档来源——特征拆得好,"出差住宿一晚能报多少钱?"的 score 最高的就是《出差规定.pdf》,而不是别的文档。
