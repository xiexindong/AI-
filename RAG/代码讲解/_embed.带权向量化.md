# `_embed` 带权向量化解析:模拟 TF-IDF 的加权累加

> 出处:`真实例子.py` 第 207~216 行,`ToyRAG._embed` 方法。

```python
def _embed(self, text: str) -> list[float]:
    vec = [0.0] * VEC_DIM
    for feat in _text_features(text):
        # 见过该特征 → 用它的 IDF 权重;没见过(通常是查询里的生词)→ 给中高权重
        w = self.idf.get(feat, 1.5)
        fv = _char_vec(feat)
        for i in range(VEC_DIM):
            vec[i] += fv[i] * w
    norm = math.sqrt(sum(v * v for v in vec)) or 1e-9
    return [v / norm for v in vec]
```

---

## 一、这段代码在干嘛(一句话)

> **把文本变成向量,但不再让每个字/词"平权",而是让"重要的低频词"贡献更大、高频虚词贡献更小**——这就是模拟 TF-IDF 的思想,也是它和 `embed()` 的本质区别。

---

## 二、逐行拆解

### 1. `vec = [0.0] * VEC_DIM`——准备 64 个"累加器"

```python
vec = [0.0] * VEC_DIM   # → [0.0, 0.0, ..., 0.0] 共 64 个零
```

后面每个特征向量都往这个累加器里加,最后得到整段文本的向量。

### 2. `for feat in _text_features(text)`——遍历特征词

`_text_features` 把文本拆成"单字 + 相邻双字":

```python
"报销制度" → ["报", "销", "制", "度", "报销", "销制", "制度"]
```

### 3. `w = self.idf.get(feat, 1.5)`——查这个词的权重

```python
w = self.idf.get(feat, 1.5)
```

- `self.idf` 是建库时算好的字典:`{特征词: IDF权重}`,例如 `{"报销": 1.9, "差旅": 2.1, "的": 0.4, ...}`
- `.get(feat, 1.5)`:字典里**有**这个词 → 取它的 IDF;字典里**没有**(通常是查询里的生词)→ 用默认值 **1.5**
- 为什么默认 1.5?中高权重——生词往往是关键实体,值得重视,但不能给得太高乱掉尺度

### 4. `fv = _char_vec(feat)`——取特征向量

`_char_vec` 用 FNV-1a + 可复现随机,把每个特征词映射成一个**固定的 64 维向量**(同一特征每次算都一样)。

### 5. `vec[i] += fv[i] * w`——加权累加(核心!)

```python
for i in range(VEC_DIM):
    vec[i] += fv[i] * w
```

和 `embed()` 相比,只多乘了一个 `w`:

| 函数 | 累加方式 | 效果 |
|---|---|---|
| `embed()`(第 79 行) | `vec[i] += fv[i]` | 每个词**平权**,"报销"和"的"贡献一样大 |
| `_embed()`(这里) | `vec[i] += fv[i] * w` | **重要的词贡献大**,虚词贡献小 |

**这就是 TF-IDF 的核心**:低频关键词(报销/差旅/公积金)IDF 大 → 权重高;高频虚词(的/了/是)IDF 小 → 权重低。

### 6. 归一化(两行)

```python
norm = math.sqrt(sum(v * v for v in vec)) or 1e-9
return [v / norm for v in vec]
```

- `sum(v * v for v in vec)` = 各分量平方和 = **模长的平方**
- `math.sqrt(...)` = 模长(向量长度)
- `or 1e-9`:空文本模长为 0 时,兜底成极小值,**防止除零报错**
- `[v / norm for v in vec]`:每个分量除以模长 → 向量长度变成 1

归一化的价值:**不同长度文本有了统一尺度**,相似度只比"方向"不比"长短",这样 `cosine` 才能一行退化成点积。

## 三、IDF 是谁建的?权重怎么确定的?

### 1. 谁建立的 → `ingest()` 方法(建库时一次性执行)

`self.idf` 不是写死的,是**程序自己统计出来的**。执行时机:

```python
# main() 里(第 289~291 行):
docs = load_and_split()
rag = ToyRAG(llm=MockLLM())
rag.ingest(docs)      # ← 就是这次调用,内部把 self.idf 算好了
```

`ingest()` 是"建库"入口,它干三件事(第 219~232 行):

```python
def ingest(self, docs):
    n = len(docs)                         # ① 文档总数(14)
    df = Counter()                        # ② 统计 → 算出 idf
    ...
    self.idf = {f: math.log(n / (1 + c)) + 1.0 for f, c in df.items()}
    for d in docs:                        # ③ 向量化 + 存储
        self.chunks.append(d)
        self.vectors.append(self._embed(d["text"]))
```

**建库一次,idf 就固定了**,之后所有查询都复用这份权重字典。

### 2. 确定权重的完整流程(三步)

**第 1 步:统计"文档频率 df"——每个词出现在几篇文档(chunk)里**

```python
df = Counter()
for d in docs:                          # 遍历全部 14 个 chunk
    for feat in set(_text_features(d["text"])):   # set 去重:同一篇里出现多次只算 1 次
        df[feat] += 1
```

结果举例:

```python
df = {"报销": 1, "差旅": 1, "的": 14, "了": 14, "加班": 1, ...}
#       ↑ 只在 1 篇出现           ↑ 14 篇全都有
```

**第 2 步:套 IDF 公式**

```python
self.idf = {f: math.log(n / (1 + c)) + 1.0 for f, c in df.items()}
#           ↑ 对每个词:log(总数 / (1 + 出现篇数)) + 1
```

公式拆开看:

| 符号 | 含义 | 例("报销") |
|---|---|---|
| `n` | chunk 总数 | 14 |
| `c` | 这个词出现在几篇里 | 1 |
| `n / (1 + c)` | 稀有度(越大越稀有) | `14/2 = 7` |
| `log(...)` | 压缩尺度(不然 7 次方差距太悬殊) | `log(7) ≈ 1.95` |
| `+ 1.0` | 保证权重 ≥ 1,不会是负数 | `1.95 + 1 = 2.95` |

**第 3 步:存进字典**

```python
self.idf = {"报销": 2.95, "差旅": 2.95, "加班": 2.95, "的": 0.94, ...}
```

### 3. 为什么这样就能"区分重要词"

- "报销"只在 **1** 篇出现 → `log(14/2)+1 ≈ 2.95`(**高**,有辨识度)
- "的"在 **14** 篇都出现 → `log(14/15)+1 ≈ 0.94`(**低**,到处都有没信息量)
- 没见过的生词 → `.get(feat, 1.5)` 给中高默认值(查询里的关键实体)

**思想一句话**:一个词在越少的文档里出现,越能"认出"是哪篇文档,权重就越高——这就是**逆文档频率**。

真实 embedding 模型内部也做了类似的事:低频词贡献大,虚词贡献小,这里手动实现了这个效果。

## 四、完整例子走一遍

建库后 `idf` 大概长这样:

```python
idf = {"报销": 2.95, "差旅": 2.95, "的": 0.94, "了": 0.94, ...}
```

给"报销的流程"向量化:

```python
text = "报销的流程"
# 特征:["报", "销", "的", "流", "程", "报销", "销的", "的流", "流程"]

for feat in ...:
    w = idf.get("报销", 1.5)   # → 2.95(关键词,权重高)
    w = idf.get("的", 1.5)     # → 0.94(虚词,权重低)
    vec[i] += fv[i] * w        # 加完:关键词把向量"拉"向它,虚词几乎不影响
```

结果:文本向量里**"报销"的方向占比大** → 问"报销能打款吗"时相似度更高,检索更准。

## 五、和 `embed()` 的分工

| | `embed()` | `_embed()` |
|---|---|---|
| 在哪用 | 全局函数,没用到过? | `ToyRAG` 的建库 + 检索 |
| 权重 | 无,平权 | IDF 加权 |
| 目的 | 演示"文本 → 向量"最小流程 | 生产级效果:提升关键词区分度 |

真实项目里这两步都被 `sentence-transformers` 等模型包办,这里拆开是为了讲清楚"加权"这个思想。

## 六、面试一句话总结

> "`_embed` 是带 IDF 权重的向量化:每个特征词的固定向量乘上它的 IDF 权重再累加,让低频关键词(报销、差旅)在文本向量中占比更大、高频虚词占比更小——模拟 TF-IDF 提升检索区分度;最后按模长归一化,让不同长度的文本统一尺度,也保证后续 `cosine` 能退化成点积。"
