# FNV-1a 算法:是什么、有什么好处、在代码里是什么意思

> 出处:由 Fowler / Noll / Vo 三人提出的**非加密哈希算法**家族,FNV 即三人姓氏首字母。
> 本文结合 `真实例子.py` 第 56~69 行讲解。

---

## 一、FNV-1a 是什么

FNV 是一族**把任意长度的字节序列压缩成一个固定大小整数(如 32 位)的哈希函数**。
它有两个变体,区别只在每个字节的操作顺序:

| 变体 | 每个字节的处理顺序 |
|---|---|
| FNV-1 | 先乘后异或:`hash = hash * prime; hash = hash ^ byte` |
| **FNV-1a**(本文) | **先异或后乘**:`hash = hash ^ byte; hash = hash * prime` |

官方推荐和实际使用最多的是 **FNV-1a**。算法本身只有两步,循环处理每个字节:

```
hash = offset_basis        # 32 位版本 = 2166136261 (0x811C9DC5)
for each byte b in input:
    hash = hash XOR b      # ① 把当前字节"混"进来
    hash = hash * prime    # ② 乘以素数扩散(32 位版本 = 16777619 = 0x01000193)
return hash                # 输出一个 0 ~ 2^32-1 的整数
```

核心代码(`真实例子.py` 第 62~65 行):

```python
h = 2166136261                       # offset_basis(32 位 FNV-1a 规范值)
for b in feat.encode("utf-8"):       # 特征字符串 → UTF-8 字节流(中文一个字占 3 字节)
    h ^= b                           # ① 先异或
    h = (h * 16777619) & 0xFFFFFFFF  # ② 再乘 prime,并 & 0xFFFFFFFF 截断成 32 位
```

两个魔法数字都是 FNV 规范里的**固定常量**,不是随便写的:
- `2166136261` = `0x811C9DC5` → 32 位 FNV-1a 的 offset basis(初始值)
- `16777619` = `0x01000193` → 32 位 FNV prime(乘法因子)
- `& 0xFFFFFFFF` → 等价于 `mod 2^32`,模拟 32 位无符号整数溢出回绕

## 二、有什么好处(为什么用它)

1. **快**。每个字节只有一次异或 + 一次乘法,没有任何分组、轮函数、查表,比 MD5/SHA 快一个数量级。适合高频调用(比如每条文本拆出几十个特征都要哈希一次)。
2. **结果稳定、确定**。同样的输入永远得到同样的输出,不依赖进程、机器、随机种子。这是它在代码里最被看重的特性(见第四节)。
3. **分布均匀**。对字符串(尤其是短字符串)散列分布好、冲突率低,适合做哈希表 key、指纹、随机种子。
4. **实现简单、零依赖**。标准库即可手写,不需要引第三方库。
5. **支持任意长度输入**。UTF-8 编码后按字节流处理,中文英文都可以。

注意它的边界:**它是非加密哈希**。设计目标不是抗碰撞攻击,不能用于密码存储、签名、防篡改等安全场景——那是 SHA-256 之类加密哈希的活。面试可以说"它牺牲安全性换取极致的简单和速度"。

### 面试补充:FNV-1a 为什么"先异或后乘"更好

乘法的特点是**把低位的差异扩散到高位**。先异或再乘,能让当前字节的信息在下一轮乘法中充分扩散,相邻/相似输入的输出差异更大(雪崩性更好);FNV-1 先乘后异或,低位信息扩散得不如 1a 充分。所以短字符串上 FNV-1a 分布更均匀。

## 三、它和其他哈希的对比

| 哈希 | 类型 | 速度 | 用途 |
|---|---|---|---|
| Python 内置 `hash()` | 非加密 | 快 | **不可靠**!字符串默认加随机盐(见下节),跨进程不稳定 |
| FNV-1a | 非加密 | 快 | 本代码用它做稳定随机种子 / 指纹 / 哈希表 key |
| MD5 / SHA-1 | 加密(已破) | 慢 | 文件校验,不用于对抗场景 |
| SHA-256 | 加密 | 慢 | 密码、签名、防篡改 |

## 四、在 `真实例子.py` 里是什么意思

### 1. 它在干什么

`_char_vec(feat)` 的目标:**把一个文本特征(单字或双字,如"报""销""报销""差旅")映射成一个固定的 64 维向量**:

```python
h = 2166136261                              # FNV-1a 算出该特征的稳定整数
for b in feat.encode("utf-8"):
    h ^= b
    h = (h * 16777619) & 0xFFFFFFFF
rng = random.Random(h)                      # 用这个稳定整数当随机种子
vec = [rng.uniform(-1.0, 1.0) for _ in range(VEC_DIM)]   # 生成 64 维随机向量
```

- 同一特征 → 同一哈希整数 → 同一个随机种子 → **每次运行生成的向量完全一样**
- 不同特征 → 不同哈希整数 → 不同随机种子 → **向量各不相同**

这样就把"字符串"变成了"可计算相似度的向量",而且是确定性的。这其实是机器学习里经典的 **Feature Hashing(特征哈希 / hashing trick)** 思想:用一个非加密哈希函数把高维稀疏特征映射到固定低维空间,无需维护词表。

### 2. 为什么不用 Python 内置的 `hash()`

这是代码注释里的关键点。Python 出于防 DoS 攻击(哈希洪水)的考虑,对字符串的 `hash()` 默认做了随机化(`PYTHONHASHSEED`):

- **同一进程内**:同一字符串哈希值相同(所以你在一次运行里看不出问题)
- **跨进程 / 每次运行脚本**:哈希值不同

后果:如果这里用内置 `hash(feat)` 当随机种子,那么**每次运行脚本,同一个特征生成的向量都不一样** → 建库时和提问时特征向量对不上 → 检索结果每次运行都不一样,无法复现、无法调试。

```python
# ❌ 不可靠:每次运行 python 真实例子.py,hash("报销") 都不一样
hash("报销")      # 这次运行 = 123456789,下次运行可能 = -987654321

# ✅ 可靠:FNV-1a 手算,永远稳定
# (对 "报销" 按 UTF-8 字节流跑完 XOR+乘法,结果永远相同)
```

### 3. 为什么用 UTF-8 编码

`feat.encode("utf-8")` 把中文字符转成字节流(一个"报" = 3 个字节),FNV-1a 是逐字节处理的哈希,所以必须先把字符串编码成字节。编码方式固定(UTF-8),保证不同环境下结果一致。

### 4. 它在整个 RAG 例子里的作用链

```
特征"报销" → FNV-1a 稳定整数 → 稳定随机种子 → 稳定 64 维向量
                                                    ↓
             文本向量 = 所有特征向量累加(embed 函数)  ↓
                                                    ↓
              问题向量 vs 文档向量 → 余弦相似度 → Top-K 检索
```

没有 FNV-1a 的稳定性,检索就会"每次运行结果不一样",整个教学例子的可复现性就崩了。它解决的是**确定性**问题——这在真实项目里对应"同样的输入必须给出同样的向量",否则缓存、回归测试、A/B 全都没法做。

---

## 五、一句话总结

> **FNV-1a 是一个又简单又快又稳定的非加密哈希**:先把字节异或进哈希值、再乘一个素数,循环处理完所有字节。在 `真实例子.py` 里,它用来把"文本特征"稳定地变成"向量种子",保证每次运行检索结果一致——因为 Python 内置 `hash()` 跨进程不稳定,不能当种子用。
