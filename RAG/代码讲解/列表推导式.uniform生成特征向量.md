# 一行代码生成 64 维随机特征向量

> 出处:`真实例子.py` 第 67 行,是 `_char_vec()` 函数的最后一步。 VEC_DIM = 64
> 结合 FNV-1a 看:前面已经把特征字符串哈希成稳定整数,这里用这个整数做种子,生成向量。

```python
vec = [rng.uniform(-1.0, 1.0) for _ in range(VEC_DIM)]
```

这一行代码干了三件事:
1. 循环 64 次(`VEC_DIM = 64`)
2. 每次生成一个 `[-1.0, 1.0)` 区间的随机浮点数
3. 把 64 个数装进一个列表 → 得到一个 64 维向量

---

## 一、逐块拆解

### 1. 整体结构:列表推导式(list comprehension)

```python
[表达式 for 变量 in 可迭代对象]
```

它等价于一个"先建空列表 → 循环 append"的写法,但更简洁、更快(Python 内部有优化):

```python
# 推导式写法
vec = [rng.uniform(-1.0, 1.0) for _ in range(VEC_DIM)]

# 等价的长写法
vec = []
for _ in range(VEC_DIM):
    vec.append(rng.uniform(-1.0, 1.0))
```

### 2. `rng.uniform(-1.0, 1.0)`:随机均匀浮点数

`rng` 是 `random.Random(h)` 对象(种子来自 FNV-1a 哈希值)。

`uniform(a, b)` 返回 `[a, b)` 区间内**均匀分布**的随机浮点数:
- 每个数出现的概率相等
- 包含下限 `-1.0`,不含上限 `1.0`
- 底层实现:`a + (b - a) * random()`,即 `-1.0 + 2.0 * random()`

### 3. `for _ in range(VEC_DIM)`:循环 64 次

- `range(VEC_DIM)` = `range(64)` → 产生 0,1,2,...,63
- `_` 是**忽略循环变量**的约定写法:循环次数有用,但"现在是第几次"这个值本身用不到,所以用 `_` 占位(读作"我不关心这个变量")

### 4. 结果:一个 64 维向量

```python
vec = [0.812, -0.341, 0.992, ..., 0.105]   # 长度 64,每个分量 ∈ [-1, 1)
```

---

## 二、为什么用 `uniform(-1, 1)` 而不是 `random()`?

| 方式 | 范围 | 特点 |
|---|---|---|
| `random()` | `[0, 1)` | 全是非负数 |
| `uniform(-1, 1)` | `[-1, 1)` | **正负各半**,期望值 0 |

在 RAG 例子里特征向量最终要**累加**成文本向量(`embed` 函数):

- 用 `uniform(-1, 1)`:不同特征的向量正负随机,累加时"相似特征互相加强、无关特征彼此抵消",语义区分度更好,更接近真实 embedding 的表现
- 用 `random()`:所有分量都是非负,累加后向量只往"正方向"堆积,区分度变差

这也是真实 embedding 模型的思路:向量是"分布"在超空间里的,有方向、有夹角,余弦相似度才有意义。

## 三、为什么"随机"但能保证稳定?

关键在种子:

```python
h = 2166136261
for b in feat.encode("utf-8"):
    h ^= b
    h = (h * 16777619) & 0xFFFFFFFF
rng = random.Random(h)                     # 种子 = FNV-1a 稳定整数
vec = [rng.uniform(-1.0, 1.0) for _ in range(VEC_DIM)]
```

- `random.Random(h)` 是**可复现随机**:给定种子 h,生成的随机序列完全确定
- 同一特征 → 同一 h → 同一序列 → **每次运行向量完全一样**
- 不同特征 → 不同 h → 不同序列 → 向量各不相同

所以它是"伪随机":看似随机,实则确定。这在 RAG 里至关重要——建库和提问必须用同一套向量,否则检索会错乱(详见 `FNV-1a.算法的好处.md`)。

---

## 四、在整个例子里的角色

```
特征字符串"报销" → FNV-1a 哈希 → 稳定种子 → uniform 生成 64 维随机向量
                                                            ↓
                文本向量 = 所有特征向量累加 → 归一化(embed 函数)
                                                            ↓
                问题向量 vs 文档向量 → 余弦相似度 → Top-K 检索
```

`VEC_DIM = 64` 是一个超参数(真实 embedding 模型常用 384/768/1536 维),维度过低区分度不够,过高则浪费存储和计算。

## 五、面试可讲的一句话

> "我用列表推导式 + `rng.uniform(-1, 1)` 把一个特征生成 64 维随机向量:循环 64 次、每次取一个 [-1,1) 均匀随机数;因为随机种子来自 FNV-1a 稳定哈希,所以同一特征每次生成的向量完全一致,保证了检索可复现。用 [-1,1) 是为了让向量正负都有,累加时相似特征互相加强、无关特征互相抵消,更接近真实 embedding 的语义区分效果。"
