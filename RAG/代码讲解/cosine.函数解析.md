# `cosine` 函数解析:`zip` / `tuple` / 点积是什么

> 出处:`真实例子.py` 第 90~92 行。

```python
def cosine(a: list[float], b: list[float]) -> float:
    """余弦相似度(向量已归一化,直接点积即可)"""
    return sum(x * y for x, y in zip(a, b))
```

---

## 一、函数目的(一句话)

> **计算两个向量的相似度,返回一个 `[-1, 1]` 之间的数:越接近 1 越相似**。因为两个向量都已归一化,所以余弦相似度直接退化成"点积",一行算完。

它回答 RAG 检索的核心问题:**问题和哪条文档最像?**

---

## 二、逐层拆解(从内往外看)

### 第 92 行整行:

```python
return sum(x * y for x, y in zip(a, b))
```

从里到外四层:**配对 → 解包 → 相乘 → 求和**。

### 1. `zip(a, b)`——"拉链"配对

把两个列表**按下标一一对应**地咬合在一起,像一条拉链:

```python
a = [1, 2, 3]
b = [4, 5, 6]

list(zip(a, b))
# → [(1, 4), (2, 5), (3, 6)]
```

- 第 0 位的 `1` 和 `4` 配对
- 第 1 位的 `2` 和 `5` 配对
- 第 2 位的 `3` 和 `6` 配对

结果里的 `(1, 4)` 就是**元组(tuple)**,见第三节。`zip` 本身返回一个迭代器,`list()` 只是方便你看清内容。

**注意**:`zip` 按较短的列表截断。两个 64 维向量长度相同,所以正好配出 64 对。

### 2. `for x, y in zip(a, b)`——解包

循环时把每一对元组拆开,赋给两个变量:

```python
for x, y in [(1, 4), (2, 5), (3, 6)]:
    # 第一轮:x=1, y=4
    # 第二轮:x=2, y=5
    # 第三轮:x=3, y=6
```

`x` 来自 `a`(第一个向量),`y` 来自 `b`(第二个向量)。

### 3. `x * y`——对应位置相乘

每一轮算 `x * y`,得到的是**两个向量在同一维度上的乘积**:

```python
1 * 4 = 4
2 * 5 = 10
3 * 6 = 18
```

### 4. `sum(...)`——全部加起来

把每一轮的乘积求和:

```python
4 + 10 + 18 = 32
```

`sum(生成器表达式)` 不产生中间列表,直接在循环中累加,省内存。

### 等价写法(帮助理解)

```python
total = 0
for x, y in zip(a, b):
    total += x * y
return total
```

一行推导式 = 上面 4 行的压缩版。

---

## 三、`tuple` 是什么

**元组(tuple)**:一种不可修改的序列,长得像列表,区别是一个 `()` 一个 `[]`:

```python
(1, 4)    # 元组 tuple——创建后不能改
[1, 4]    # 列表 list——可以 append / 修改元素
```

`zip` 配对出来的每一对都是元组。代码里没有直接写 `tuple` 这个词,它是 `zip` 返回元素的类型。

---

## 四、为什么要这么算(点积 = 余弦相似度)

### 点积的定义

两个同维度向量的点积 = 对应位置相乘再求和:

```
a·b = a₁·b₁ + a₂·b₂ + ... + a₆₄·b₆₄
```

`sum(x * y for x, y in zip(a, b))` 就是这段公式的代码翻译。

### 为什么点积就是余弦相似度

余弦相似度的完整公式:

```
cos(θ) = (a·b) / (|a| × |b|)
```

而 `embed()` 返回的向量**已经归一化**(模长 = 1),所以:

```
cos(θ) = (a·b) / (1 × 1) = a·b
```

分母消失,只剩点积——所以 docstring 才写"向量已归一化,直接点积即可"。**归一化那一步的功劳,到这里兑现了。**

## 五、完整流程例子(64 维的迷你版)

```python
# 假设两个 3 维向量(真实代码是 64 维)
a = [1.0, 0.0, 0.5]
b = [0.8, 0.2, 0.5]

# zip 配对:
#   (1.0, 0.8), (0.0, 0.2), (0.5, 0.5)

# 对应相乘再求和:
#   1.0×0.8 + 0.0×0.2 + 0.5×0.5
# = 0.8 + 0 + 0.25
# = 1.05
```

得分越高 → 方向越接近 → 文本越相似。这就是 `真实例子.py` 里检索排名的依据:

```python
scores = [(i, cosine(q_vec, d_vec)) for i, d_vec in enumerate(doc_vecs)]
scores.sort(key=lambda t: t[1], reverse=True)   # 按得分从高到低排 Top-K
```

## 六、大白话

- `zip` 像**拉链**:把两个列表同一位置的两个数"咬"成一排
- `x * y` 像**对暗号**:问的是"这个维度上,咱俩的方向一致吗?"——方向一致乘积大,方向相反乘积为负
- `sum` 像**记账**:把 64 个维度的"一致程度"加起来,得到总分

最后用总分排名:**谁总分高,谁就和问题最像,谁就被检索出来喂给 LLM**。

---

## 七、面试一句话总结

> "`cosine` 计算两个归一化向量的点积作为相似度:`zip(a, b)` 把两向量按位置配对,`x * y` 逐维相乘,`sum` 求和。因为 `embed` 已把向量归一化到模长 1,完整余弦公式的分母等于 1,直接退化成点积——所以这一行就是余弦相似度,得分越高代表两段文本语义越接近,是 RAG 检索排序的依据。"
