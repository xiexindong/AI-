# 为什么这样计算:`h * 16777619`、`& 0xFFFFFFFF`、`Random(h)`

> 出处:`真实例子.py` 第 65~66 行,FNV-1a 循环的最后一步 + 用它做随机种子。

```python
h = (h * 16777619) & 0xFFFFFFFF   # ① 乘素数扩散 → 截断成 32 位
rng = random.Random(h)            # ② 用这个整数做随机种子
```

两行各司其职:
- 第 65 行完成 FNV-1a 的"**扩散**"步,并让哈希值始终是一个 32 位整数
- 第 66 行把哈希整数交给 `random.Random`,桥接"字符串 → 稳定随机向量"

---

## 一、为什么是 `h * 16777619`(乘一个素数)

### 1. 乘法的作用:把差异从低位"扩散"到整个数

上一步 `h ^= b` 只把当前字节的信息混进了 `h` 的**低 8 位**(高 24 位异或 0 不变)。
如果到这里就结束,哈希值只依赖低 8 位,不同特征很容易撞出同一个哈希值。

乘法能把低位的差异按倍数放大、扩散到高位。比如:

```python
h = 0x00000001    # 和
h = 0x00000002    # 乘同一个素数后,结果在 32 位里差异散布开
```

数学本质:乘奇数相当于在二进制里做**多次移位 + 相加**,把输入每一位的信息"搅"到输出的所有位上。

### 2. 为什么必须用素数(不能随便挑一个数)

乘法是在"模 2^32"的环里进行的,乘数不同,信息保留程度天差地别:

- 乘**偶数**(如 2、100):低位信息会丢失。比如乘 2,结果最低位永远是 0,低 1 位的信息全没了;乘 4 丢 2 位。信息丢失 → 哈希分布不均匀 → 冲突变多。
- 乘**素数**(如 16777619):与 2 互质,每一位的信息都保留并参与扩散,分布最均匀。

这是哈希算法设计的通用原则:**素数乘法器 + 溢出回绕**能最大化"雪崩效应"(输入微小变化 → 输出大幅变化)。

### 3. 16777619 这个数从哪来

`16777619 = 0x01000193`,是 FNV 规范钦定的 32 位 prime,和 `2166136261 = 0x811C9DC5`(offset basis)是一对官方常量,不是随手写的。它是个大奇数(素数),乘法扩散效果好,而且该数字形态特殊,在硬件上可以拆成移位 + 加法快速计算。

---

## 二、为什么 `& 0xFFFFFFFF`(截断成 32 位)

### 1. 不截断会怎样

Python 的 `int` 是任意精度的,`h * 16777619` 每循环一次就大一点,处理完一整个字符串后会变成一个几百上千位的巨数,而且没有上限、不可预测。

### 2. `& 0xFFFFFFFF` 是什么

按位与 `0xFFFFFFFF`(32 个 1)= **只保留低 32 位**,等价于 `mod 2^32`,也就是 C 语言里 `uint32_t` 自然溢出回绕的效果:

```python
(h * 16777619) & 0xFFFFFFFF     # 数学上等价于 (h * 16777619) % 2**32
```

用 `&` 而不是 `%`,是因为位运算比取模快,而且对 2 的幂两者结果完全一致。

### 3. 截断带来三个好处

1. **范围固定**:不管文本多长,哈希值永远是 `0 ~ 2^32-1` 的整数 → 可以稳定地当随机种子、当哈希表 key
2. **防失控膨胀**:每次乘法后拉回 32 位,数字不会无限变大,性能稳定
3. **配合素数乘法形成"回绕混叠"**:溢出丢掉的高位信息在下一次循环被重新混进来,这正是 FNV 哈希分布均匀的原因之一

---

## 三、为什么 `rng = random.Random(h)`(用整数做种子)

### 1. Random(seed) 是可复现的

`random.Random(h)` 用整数种子初始化梅森旋转算法(MT19937,Python 默认随机数生成器)。**同一个种子,生成的随机数序列完全一样。**

```
特征"报销" → h(固定整数)→ 随机序列(固定)→ 64 个 uniform 数(固定)
```

这就是前面说的"伪随机"——看似随机,实则完全确定。没有这一步,同一特征每次运行的向量会不一样,检索结果就无法复现。

### 2. 为什么不用全局的 `random.uniform(...)`

`random` 模块的全局函数(如 `random.uniform()`)共享一个进程级种子,特点:
- 全局序列会被所有特征"消耗",互相干扰,无法为单个特征独立取随机数
- 想要可复现必须手动 `random.seed(...)`,而全局 seed 会重置整个模块状态,容易出 bug

用独立对象 `random.Random(h)` 则每个特征有**自己独立的随机序列**,互不干扰,种子直接来自该特征本身——干净、隔离、可控。

### 3. 为什么不直接拿 h 当向量

h 只是一个整数,而向量需要 64 个互相独立的数。`Random(h)` 就是把"一个种子"扩成"一串数"的标准工具,均匀分布、随机性强,且与种子一一对应。

---

## 四、完整链条(两行代码在全局中的位置)

```
特征字符串"报销"
   │
   ├─ h = 2166136261            FNV-1a 初始化
   ├─ for 每个字节: h ^= b     注入:字节信息进低 8 位
   ├─ h = (h * 16777619)       扩散:低位差异搅到全 32 位
   ├─       & 0xFFFFFFFF       截断:保持 32 位固定范围
   │
   ▼
h = 稳定整数(0 ~ 2^32-1)
   │
   ├─ rng = random.Random(h)   种子 → 可复现随机序列
   ├─ [rng.uniform(-1,1) ×64]  生成 64 维随机向量
   │
   ▼
特征向量(每次运行完全一致)
```
