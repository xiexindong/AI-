# 08 RAG 的局限性与弊端

> 面试题:**"RAG 有什么缺点?在什么场景下不适用?"**
> 面试官问这个,是想看你是"真用过"还是"只背概念"。

---

## 一、原理

RAG 的架构决定了它的天花板:

```
知识在"外部"而不是"模型内"
  ↓
每一步都可能掉链子:
  文档解析 → 切分 → 向量化 → 检索 → 排序 → 拼 prompt → LLM 生成
  ↑任何一环出问题,最终答案就受影响
```

RAG 本质是**用系统复杂度换知识实时性**——这个交易不总是划算。

---

## 二、通俗理解(大白话)

```
RAG = 考试翻书
翻书的缺点:
  ① 书里没有的题 → 翻不到 → 只能编(幻觉)
  ② 书太乱/查得慢 → 翻错页 → 答错
  ③ 考场只让带几页纸 → 材料带不全
  ④ 每次翻书都慢半拍 → 比背书的人慢
  ⑤ 书会被别人看到 → 隐私风险
```

**一句话:RAG 再强,也强不过"知识库里有的东西";而知识库没有的东西,它和纯 LLM 一样会编。**

---

## 三、例子

```
局限 1:幻觉消不干净
  问:「2026 年公司年会奖品是什么?」
  知识库没有 → 检索到无关材料 → LLM 基于无关材料编了一个
  → 表面"有出处",实际还是假的

局限 2:检索失败 = 全盘失败
  文档里写「核销」,用户问「报销」→ embedding 没对齐
  → 正确答案在库里,但没被召回 → 答错

局限 3:上下文塞不下
  答案横跨 10 个 chunk,Top-3 只取到 3 个 → 信息残缺

局限 4:延迟
  纯 LLM:1 次调用 ≈ 500ms
  RAG: 检索 30ms + 拼 prompt + LLM 调用 ≈ 800ms+

局限 5:知识库维护
  文档改了,旧向量没删 → 新旧两版混着回答
```

---

## 四、分析

### RAG 的 6 大局限(面试按这个答)

| # | 局限 | 原因 | 缓解 |
|---|---|---|---|
| 1 | **幻觉无法根除** | LLM 仍可能不遵循材料/检索到无关材料 | 检索质量 + prompt 强制 + 拒答约定 |
| 2 | **依赖检索质量** | 召回是天花板,检索不到=答不好 | 多路召回、query 改写、rerank |
| 3 | **上下文受限** | 窗口有限,材料带不全 | 压缩、RSE 抽取关键片段 |
| 4 | **延迟增加** | 多一次检索+拼装 | 缓存、更快的索引、异步 |
| 5 | **维护成本高** | 切分/向量化/权限/版本要持续管 | 自动化 pipeline + 监控 |
| 6 | **安全与隐私** | 向量库可被越权访问/反推 | 权限过滤 + 审计 + 加密 |

### 什么场景 RAG 不合适(反着说)

```
1. 知识高度动态且答案要求极准(金融实时报价)→ 检索可能慢/旧
2. 问题必须用"推理+整合"而不是"查资料"(数学证明)→ RAG 帮不上
3. 高并发低延迟场景(毫秒级接口)→ 检索开销不可接受
4. 数据全在表格/代码/多模态里,文本化损失大 → 解析成本高
5. 无知识库可用(纯闲聊/创作)→ RAG 没意义
```

---

## 五、优点(辩证看)

> 局限是相对的,同样的架构也带来了不可替代的好处,面试要"先抑后扬":

1. **知识实时更新**:改文档即生效,微调做不到
2. **答案可溯源**:每句话有出处,审计友好
3. **成本低于微调**:不训模型
4. **数据合规**:私有数据不进模型参数
5. **可解释可调试**:Top-K 能打印,问题能定位

> 面试话术:"RAG 的局限都是'工程问题',不是'方向问题'——幻觉用检索质量+拒答缓解,延迟用缓存+索引优化,维护用 pipeline 自动化。它换来的实时性、溯源、低成本是微调给不了的。"

---

## 六、弊端(总结性)

```
① 系统复杂度高:6 步链路,每步都要调优
② 天花板=检索质量:召回是上限,LLM 只是放大器
③ 双倍出错面:检索错 + 生成错,叠加
④ 无成熟标准:切分/评测各家自建,难迁移
⑤ 长尾问题:冷门问题、多跳问题、跨文档问题效果差
⑥ 资源消耗:向量库 + embedding + LLM,三个系统都要钱
```

---

## 七、面试一句话总结

> "RAG 的局限根源是**'知识在外部'**:**检索不到就答不好**(天花板效应)、**幻觉不能根除**(LLM 仍会不遵循材料)、**延迟和成本增加**、**知识库要持续维护**、还有**隐私和越权风险**。缓解靠多层:检索质量、prompt 强制、拒答约定、缓存、权限过滤。所以遇到**答案要求毫秒级、必须推理整合、或纯闲聊**的场景,RAG 不是最优解。但它的实时性、可溯源、低成本,让它在企业知识问答里仍然是最主流的方案。"
