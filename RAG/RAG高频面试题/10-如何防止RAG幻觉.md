# 10 如何防止 RAG 幻觉

> 面试题:**"RAG 怎么防止幻觉?答错/编造怎么处理?"**
> 幻觉是 RAG 面试里最常被深挖的话题。

---

## 一、原理

**幻觉(Hallucination)= LLM 说出知识库里没有、或与材料不符的内容。**

RAG 的幻觉来源(按链路):

```
① 检索层:召回的材料和问题不相关 → LLM 基于错材料"合理编造"
② 上下文层:材料相关但不完整 → LLM 脑补缺失部分
③ 生成层:LLM 不遵循"只用材料"指令 → 凭训练记忆瞎说
④ 数据层:文档本身有错/过时 → "忠实转述了错误"
```

**关键认知:RAG 不能根除幻觉,只能"大幅降低 + 兜底拦截"。** 面试先承认这一点,再说怎么防。

---

## 二、通俗理解(大白话)

```
幻觉 = 员工回答问题时"自由发挥":

  RAG 的作用 = 给他一本资料书
  但:
  ① 书给错了页(检索不准)→ 照错页念(错但不自知)
  ② 书只给半页(材料不全)→ 剩下半页自己编
  ③ 他不爱看书(LLM 不守规矩)→ 凭记忆瞎说
  ④ 书本身就是错的(数据脏)→ 念错了还挺自信

防幻觉 = 保证"给的页对、给的页全、逼他看书、书本身没错"
```

---

## 三、例子

```
场景:问「公积金提取条件」

✅ 正常:
  检索到「公积金提取:租房可每季度提取一次」→ LLM 照材料回答

❌ 幻觉 1(检索错):
  检索到「公积金缴纳:按 12% 缴纳」→ LLM 答"公积金按 12% 提取"
  ——材料相关但没回答提取问题,LLM 张冠李戴

❌ 幻觉 2(材料不全):
  材料只说「租房可提取」→ 用户问「买房提取」→ LLM 编"购房可提取"

❌ 幻觉 3(不守规矩):
  材料是「年假 10 天」→ LLM 凭记忆答"年假 15 天"

❌ 幻觉 4(数据脏):
  文档里写了「试用期 12 个月」(错的)→ LLM 照念,错得理直气壮
```

---

## 四、分析

### 防幻觉的 5 层防线(面试按层答)

| 层 | 手段 | 作用 |
|---|---|---|
| ① 数据层 | 清洗文档、校验来源 | 从源头杜绝"错数据" |
| ② 检索层 | 提升召回质量 + Rerank + 相似度阈值 | 保证材料**相关** |
| ③ 上下文层 | 上下文压缩、RSE 抽关键片段、多路召回 | 保证材料**够且不吵** |
| ④ 生成层 | prompt 强制"只用材料"+ 拒答约定 | 逼 LLM 不自由发挥 |
| ⑤ 兜底层 | 来源标注 + 引用 + 事后校验 | 错了也能被发现 |

### 关键手段详解

**手段 A:prompt 强制 + 拒答(最便宜有效)**

```
system prompt:
"你只能根据提供的资料回答,资料里找不到就说
『知识库中未找到相关内容,请咨询 HR』,严禁编造。"
```

```
`真实例子.py` 就是这么做的:
  问「年会抽奖奖品」→ 检索不到 → LLM 答"知识库中未找到相关内容" ✅
```

**手段 B:相似度阈值(防止"凑合着答")**

```
score < 0.3 → 判定"没把握" → 直接拒答,不硬答
低分材料宁可不用,也不能喂给 LLM 编
```

**手段 C:来源可溯源(让幻觉"显形")**

```
答案末尾标注:【来源:员工手册.pdf 第 15 页】
用户/系统能核对 → 幻觉无处藏
```

**手段 D:混合检索 + Rerank(提高材料相关度)**

```
向量 + 关键词双路召回 → 融合 → Rerank
关键词能捞到"专有名词/精确数字",补向量短板
```

**手段 E:自检/校验(生成后检查)**

```
① 让 LLM 自检:回答里哪些句子在材料中找不到依据?
② 引用对齐:每个结论要求对应材料片段
③ 人工抽检:高价值场景(医疗/金融)加人工复核
```

### 面试必答的"完全消灭幻觉"陷阱

```
如果面试官问"能不能做到零幻觉?"——答案:不能。
LLM 是概率模型,任何防护都是"降低概率 + 提高发现率"。
诚实回答:"零幻觉做不到,我的目标是:答错率降到可接受范围,且错了能被发现。"
```

---

## 五、优点(防幻觉措施的好处)

1. **可溯源**:答案带来源,审计友好
2. **拒答机制**:减少"自信地胡说"
3. **可评估**:幻觉率可以量化(人工抽检比例)
4. **成本可控**:prompt 层方案零成本,检索层方案可加可减
5. **提升整体可信度**:用户敢用,产品能上线

---

## 六、弊端(这些措施的代价)

1. **拒答会误伤**:严格阈值下,本来答得出的问题也被拒(召回率→可用率下降)
2. **prompt 不是万能的**:LLM 仍可能无视指令(尤其小模型)
3. **检索层优化成本高**:多路召回、rerank 都要资源
4. **自检增加延迟**:二次调用 LLM,成本翻倍
5. **防了"编造"防不了"错料"**:源头数据错,下游全错
6. **阈值难调**:相似度阈值定高了可用性差,定低了防不住幻觉

---

## 七、面试一句话总结

> "RAG 的幻觉我分四层防:**数据层**清洗保证源没错;**检索层**提高召回质量+rerank+相似度阈值,保证材料相关;`prompt 层`强制'只用材料,找不到就拒答'(真实例子.py 就是这么做的);**兜底层**答案带来源标注、可人工抽检。但**零幻觉做不到**——LLM 是概率模型,我的目标是**把幻觉率压到可接受范围,且每条幻觉都能被发现**(可溯源),这才是工程上务实的答案。"
