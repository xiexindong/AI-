# 04 什么是 Embedding 与向量相似度

> 面试题:**"什么是 Embedding?向量相似度怎么算?"**
> 对照代码:`示例.py` 的 `fake_embed` 与 `cosine_sim`。

---

## 一、原理

**Embedding(嵌入)= 把一段文本映射成一串固定长度的数字(向量),让"语义相近的文本,向量也相近"。**

```
"猫"    → [0.8, 0.2, 0.1]
"猫咪"  → [0.78, 0.22, 0.09]   ← 和"猫"很像(语义近)
"汽车"  → [0.1, 0.9, 0.3]      ← 和"猫"不像(语义远)
```

**向量相似度** = 用数学量(余弦相似度 / 点积)量化两个向量"像不像":

```
cos(A, B) = (A·B) / (|A| × |B|)
          = 对应分量相乘求和,再除以两个向量的长度乘积
```

- 完全相同 → 1.0
- 完全不相关 → 接近 0
- 完全相反 → -1.0

---

## 二、通俗理解(大白话)

把每个词想成"一张寻人画像"上的特征:

```
"猫"的画像:  毛茸茸(0.8) 四条腿(0.7) 会喵(0.9) 有轮子(0.0)
"猫咪"的画像: 毛茸茸(0.79) 四条腿(0.72) 会喵(0.88) 有轮子(0.0)
"汽车"的画像: 毛茸茸(0.0) 四条腿(0.0) 会喵(0.0) 有轮子(0.95)

对比画像特征,一看就知道"猫"和"猫咪"是一家人,"汽车"不是。
向量相似度 = 自动完成这个"特征对比"的数学工具。
```

**为什么能"语义匹配"?** 因为 embedding 模型是拿"海量相似文本对"训练出来的:相似文本被压到向量空间里相近的位置。

## 三、例子(手算一遍余弦相似度)

```python
# 示例.py 里的核心(真实项目 = 调 OpenAI / bge 的 embedding API)
def fake_embed(text: str) -> list[float]:
    """把文本变成 64 维向量(教学版)"""

def cosine_sim(a, b):
    dot = sum(x * y for x, y in zip(a, b))   # 点积:对应分量相乘求和
    norm_a = sum(x * x for x in a) ** 0.5    # 向量长度
    norm_b = sum(y * y for y in b) ** 0.5
    return dot / (norm_a * norm_b)           # 除以长度 → 只看"夹角",不看"长度"
```

```
手算 2 维例子:
A = [1, 0]  (往"报销"方向)
B = [0.9, 0.1]
C = [0, 1]  (往"请假"方向)

cos(A, B) = (1×0.9 + 0×0.1) / (1 × 0.906) ≈ 0.99  ← 很像
cos(A, C) = (1×0 + 0×1) / (1 × 1) = 0            ← 不像
```

**真实效果(`真实例子.py`)**:

```
问「打车费能报销吗?」
  → 向量检索命中「差旅报销:出差产生的打车费、交通费…」
  → score=0.3448 —— 因为它和「打车费」语义最近(其实文档里写的是交通费)
这就是语义检索:不靠字面匹配,靠"意思相近"。
```

## 四、分析

### 为什么是"余弦"而不是"距离"?

| 指标 | 公式 | 特点 |
|---|---|---|
| 余弦相似度 | A·B / (\|A\|\|B\|) | **只看方向(语义),不看长度**,范围 [-1,1] |
| 欧氏距离 | √Σ(Ai-Bi)² | 看绝对差异,受向量长度影响 |
| 点积 | ΣAi·Bi | 快,但受长度影响 |

- Embedding 模型一般输出**归一化向量**(长度=1),此时**点积 = 余弦**,等价
- 面试说:"我们用的是余弦相似度;归一化之后直接点积即可(见 `真实例子.py` 的 cosine)"

### 关键原则:同一个模型贯穿

```
建库时用 bge-small 向量化 → 查询也必须用 bge-small
不同模型的向量空间不同,"猫"在 A 模型的位置 ≠ B 模型的位置,比不了
```

### 维度怎么选

| 模型 | 维度 | 场景 |
|---|---|---|
| all-MiniLM-L6-v2 | 384 | 英文轻量 |
| bge-small-zh-v1.5 | 512 | 中文 |
| bge-large-zh-v1.5 | 1024 | 中文高精度 |
| text-embedding-3-large | 3072 | 最强但贵 |

## 五、优点

1. **语义匹配**:"打车费"能匹配"交通费",关键词搜不到
2. **跨语言**:多语言模型能让中英文文档互相匹配
3. **稠密高效**:1024 维向量足够表达复杂语义
4. **通用**:文本、图片、音频都能 embedding(多模态)
5. **可离线**:开源模型本地跑,数据不出域

---

## 六、弊端

1. **不精确匹配**:同义词可能匹配错(需要区分语境时,如"苹果"公司 vs 水果)
2. **对罕见词/专业术语弱**:没训练过的词,向量可能"看不懂"
3. **维度诅咒**:维度过高时,所有向量都"差不多远",区分度下降
4. **不可解释**:向量是人眼看不懂的数字,难调试
5. **模型版本敏感**:换模型必须重建整个库
6. **计算成本**:大规模向量相似度计算要吃 CPU/GPU
7. **隐私风险**:向量本身可能泄露语义(可被反推近似原文)

---

## 七、面试一句话总结

> "Embedding 是**把文本映射成高维向量**,让语义相近的文本在向量空间里相邻;向量相似度用**余弦相似度**计算(归一化后可简化为点积)。RAG 用它实现**语义检索**——'打车费'能召回'交通费',这是关键词搜索做不到的。两个要点:**建库和查询必须用同一个模型**,以及**余弦只看方向不看长度**。"
