# 02 RAG 的完整工作流程

> 面试题:**"RAG 从文档到回答,完整流程走一遍?"**
> 对照代码:`真实例子.py`(完整闭环)、`示例.py`(手搓向量库)。

---

## 一、原理

RAG 分**两个阶段**,各 3 步,共 6 步:

```
【建库阶段(离线,做一次)】
  ① 文档加载 → ② 切分 chunk → ③ 向量化入库

【问答阶段(在线,每次提问)】
  ④ 问题向量化 → ⑤ 向量检索 Top-K → ⑥ 拼 prompt 交给 LLM
```

建库只做一次,之后新文档增量入库;问答每次实时跑。

---

## 二、通俗理解(大白话)

```
建库 = 把一本书"做成目录":
  拆书(切分)→ 每页贴标签(向量化)→ 摆进图书馆(向量库)

问答 = 读者问问题:
  把问题也贴个标签(向量化)→ 在图书馆找最像的 3 页(检索)
  → 把这几页复印件放读者桌上(拼 prompt)→ 让读者照抄回答(LLM 生成)
```

**核心思想:先"把书存好",再"按问题查书",最后"照着念"。**

---

## 三、例子(跟着 `真实例子.py` 走一遍)

```
🏢 场景:HR 知识库(员工手册/报销/出差/入职/公积金,共 5 份文档)
```

### 建库阶段

```python
docs = load_and_split()      # ① 加载文档 → 切分 → 14 个 chunk
rag = ToyRAG(llm=MockLLM())
rag.ingest(docs)             # ③ 向量化 + 存库 → 📥 共 14 个 chunk,来源 5 份文档
```

```
① 文档:员工手册.pdf、报销制度.pdf、出差规定.pdf…
② 切分:每份文档拆成 2~4 个 chunk(如「出差住宿标准:…500元」)
③ 入库:每个 chunk → 加权向量 → 存进 self.vectors
       同时统计 IDF(哪个词稀罕、哪个词常见)
```

### 问答阶段

```python
rag.ask("出差住宿一晚能报多少钱?")
```

```
④ 问题向量化:用建库时同一套 IDF 权重,把问题变成向量
⑤ 检索:和 14 个 chunk 向量算余弦相似度,排序取 Top-3
   → score=0.289  [出差规定.pdf] 出差住宿标准:…500 元 ✅
⑥ 拼 prompt:
   "请只根据以下公司内部资料回答,不要编造。
    材料:[检索到的 3 段]
    问题:出差住宿一晚能报多少钱?"
   → LLM:"一线城市不超过 500 元/晚。"
```

### 防幻觉兜底

```
问「年会抽奖的奖品」→ 知识库里没有 → 检索不到相关材料
→ LLM 按 prompt 约定回答:"知识库中未找到相关内容" ✅ 不编
```

## 四、分析

### 每一步都可能成为瓶颈

| 步骤 | 常见问题 |
|---|---|
| 切分 | 粒度不对 → 上下文断裂 / 召回不准 |
| 向量化 | 模型选错 → 中文文档用英文模型,召回差 |
| 检索 | Top-K 太小 / 排序不准 / 无权限过滤 |
| 拼 prompt | 材料顺序乱、没标题、超出窗口 |
| LLM 生成 | 不遵循"只用材料"的指令 → 仍会编 |

> 这也是《召回不准 上下文断裂 质量忽高忽低.md》的排查思路:逐层定位。

### 关键原则:同一个 embedding 模型贯穿始终

建库和问答必须用**同一个模型**,否则向量空间不同,相似度没意义。

---

## 五、优点

1. **闭环清晰**:每一步职责单一,方便排查和优化
2. **模块化**:切分、检索、生成可独立升级(换 embedding / 加 rerank)
3. **增量扩展**:新文档进来,只做"切分+入库",不动已有部分
4. **可观测**:检索的 Top-K 可以打印出来,定位问题在哪个环节

---

## 六、弊端

1. **两阶段引入复杂度**:比纯 LLM 多一套建库 + 检索系统
2. **建库有一次性成本**:切分、向量化、IDF 统计要跑一遍(大库很耗时)
3. **数据一致性**:文档更新时旧向量没删干净 → 新旧版本混着召回
4. **端到端优化难**:检索和生成分开调优,链路越深越难全局最优
5. **延迟叠加**:检索 + rerank + 生成,每一层都在加时间

---

## 七、面试一句话总结

> "RAG 流程分建库和问答两阶段、共 6 步:离线把文档切分、向量化、带 IDF 统计入库;在线把问题向量化,和库内向量做余弦相似度取 Top-K,拼进 prompt 交给 LLM 生成,检索不到就按约定拒答防幻觉。核心是**建库一次、问答多次、同模型贯穿、分步可查**——任何一步出问题都能单独定位。"
