# 09 什么是 Rerank(重排序)

> 面试题:**"为什么召回以后还要做 Rerank?"**

---

## 一、原理

RAG 的排序分**两个阶段**:

```
第一阶段(粗召回):向量库用 embedding 相似度,快速捞出 Top-100
                    (快,但"语义相近"≠"真的相关")
第二阶段(Rerank):用交叉编码器(cross-encoder),对 Top-100 精排,取 Top-3
                    (慢一点,但"更懂"query 和候选的关系)

用户 query ──┐
             ├── Cross-Encoder ──→ 相关度分数 ──→ 精排 ──→ 取 Top-3
候选 chunk ──┘
```

**为什么向量检索排序不够准?** 因为 embedding(双编码器 bi-encoder)是**分别**把 query 和 chunk 编码成向量,再算余弦——"语义像"不代表"一定回答了这个问题";而 **Rerank 是把 query 和 chunk 拼在一起,交给模型看"这段材料到底回答没回答这个问题"**,更精准。

---

## 二、通俗理解(大白话)

```
向量检索  = 海选:从 100 万人里按"长得像"挑 100 个
Rerank    = 终审:面试官一对一聊,从 100 个里挑 3 个真正能干的

海选看"像不像",终审看"行不行"。
```

```
向量检索: "报销" 和 "报销流程" 向量很近 → 排前面
Rerank:   把「问题:报销需要什么材料?」和「材料:报销需保留发票…」
          拼一起给模型看 → 模型判断"这段材料确实回答了这个问题" → 打高分
```

---

## 三、例子

```
用户问:「年假有多少天?」

向量检索 Top-3(按语义相似度):
  #1 "员工请假流程:提前 3 天提交申请"  ← 语义像(都是请假/假期)
  #2 "年假全年 10 天,试用期按比例折算"   ← 正确答案,却排第 2
  #3 "工资发放:每月 15 日"             ← 不太像

Rerank 后(按"是否回答了问题"):
  #1 "年假全年 10 天,试用期按比例折算"   ← 正确答案升到第 1 ✅
  #2 "员工请假流程:提前 3 天提交申请"
  #3 "工资发放:每月 15 日"
```

**效果数字(常见报告)**:Top-1 命中率从 60%~70% 提到 80%~90%。

---

## 四、分析

### 为什么 embedding 不够,非要 Rerank?

| 对比 | 双编码器(bi-encoder,embedding) | 交叉编码器(cross-encoder,rerank) |
|---|---|---|
| 输入 | query 单独编码、chunk 单独编码 | **query + chunk 拼一起**编码 |
| 对交互的理解 | 弱(只看全局相似) | 强(能看"是否真回答了问题") |
| 速度 | 快(向量可预先算好) | 慢(每条候选都要现算) |
| 精度 | 粗 | 精 |
| 场景 | 海选 Top-100 | 精排 Top-3 |

### 标准流水线(面试直接背)

```
query → 向量库粗召回 Top-100 → rerank(交叉编码器)→ Top-3 → 拼 prompt → LLM
```

### 延迟预算

```
rerank 100 条:交叉编码器约 50~200ms(取决于模型大小)
预算不够 → 粗召回降到 Top-30 再 rerank,召回率几乎不掉
用户接受:对话 <200ms,搜索 <500ms
```

### 常见 Rerank 模型

| 模型 | 特点 |
|---|---|
| `bge-reranker-v2-m3` | 中文友好,效果好 |
| `bge-reranker-base` | 通用轻量 |
| Cohere Rerank | API,效果好 |
| 自定义微调 rerank | 领域数据微调,最强但成本高 |

---

## 五、优点

1. **显著提升排序质量**:Top-1 命中率提升 10~20 个点
2. **能理解"问题-材料"的匹配**:比纯向量更懂"答没答上"
3. **不用重建向量库**:只加一个在线环节,不动离线数据
4. **可控精度/速度**:通过候选数(100→30)调节
5. **对噪声更鲁棒**:过滤掉"语义像但没回答"的干扰项

---

## 六、弊端

1. **额外延迟**:每条候选要过一遍模型,Top-100 就是 100 次推理
2. **计算成本**:交叉编码器比 embedding 贵
3. **不能弥补召回**:召回的 Top-100 里没有正确答案,rerank 也救不回来
4. **模型选择成本**:要选/调 rerank 模型,领域数据还得微调
5. **有增益上限**:库很小(几百条)或效果已很好时,提升有限

---

## 七、面试一句话总结

> "Rerank 是**检索后的精排环节**:向量库用双编码器粗召回 Top-100(快但只看'语义像'),再用交叉编码器把 query 和候选**拼起来**判断'这段材料是否真的回答了问题',精排取 Top-3。它能提升 Top-1 命中率 10~20 个点,代价是增加几十到几百毫秒延迟。但**它只能优化排序,不能弥补召回**——Top-100 里没答案,rerank 也变不出来。"
