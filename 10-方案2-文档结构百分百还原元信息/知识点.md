# 方案 2：文档结构百分百还原 —— 元信息（Metadata）保留

## 一、解决什么问题？

> **Slogan：** 让数据有来处，让回答可追溯。

传统 RAG 切片时，会把 PDF 里的结构信息**全部扔掉**——标题层级、章节、页码、表格在哪、脚注是什么，统统不要，最后只留下一坨"纯文本"。

后果就是：
- 检索到了一句话，不知道这句话来自第几章第几页
- 表格里的数字不知道表头是什么（"营收 2000 万"——哪一年的？哪个业务线的？全丢了）
- 合同条款"第 8.3 条"切了之后只剩半句，根本无法判断完整性

本方案核心：**切片之前先把 Metadata（元信息）全取出来，并且强制和每个切片绑定。**

---

## 二、必须保留的 6 类元信息结构

> （图中红框打勾的就是这 6 条，面试官问你就直接背）

```
┌─────────────────────────┬─────────────────────────┐
│ 左侧三类（文档结构）       │ 右侧三类（内容单元）      │
├─────────────────────────┼─────────────────────────┤
│ ① 页码、页眉页脚          │ ④ 表格编号与表头          │
│ ② 标题层级（H1~H6）       │ ⑤ 图片说明与脚注          │
│ ③ 章节结构与段落边界      │                         │
└─────────────────────────┴─────────────────────────┘
```

| 序号 | Metadata | 为什么一定要留？ | 反例：不留会怎样？ |
|------|----------|----------------|-----------------|
| ① | 页码、页眉页脚 | 回答时可以精确到页，合同/法律场景硬要求 | 面试官问"这条在第几页？"，你答不上来 → 直接挂 |
| ② | 标题层级（H1~H6） | 知道一句话属于"第几章第几节"，方便做上下文注入（下一个方案会讲） | 切片只剩一句"违约金为 10%"，不知道属于哪一章 → 语义全丢 |
| ③ | 章节结构与段落边界 | 切片不跨章，防止把不相关的两段拼在一起 | 把"甲方权利"和"乙方义务"拼在一个 chunk 里 → 检索回答胡说八道 |
| ④ | 表格编号与表头 | 表格数字必须和表头绑定，不然数字没意义 | 表格切片只剩"2000 万"，不知道是"营收"还是"负债" → 完全失真 |
| ⑤ | 图片说明与脚注 | 图/表下方的小字体注释往往是关键定义 | 脚注写了"以上数据按 US GAAP 计算"，你丢了 → 数字解读完全错误 |

## 三、不同类型 PDF 的针对性范例

光有通用 Metadata 还不够，**不同业务场景的 PDF，切片时要额外加「该场景专用」的元信息字段**。图里给了两个经典面试案例：

### 📑 合同类 PDF 范例（法律/采购场景）

> **切片时需精准标记：这是第几章、第几条、以及跨页状态。**

```json
// 合同类 PDF 的一个切片 Chunk 示例
{
  "chunk_text": "8.3 若甲方逾期付款超过 30 天，乙方有权单方面解除合同。",
  "metadata": {
    "page": 12,
    "chapter": "第 8 章 违约责任",
    "clause": "第 8.3 条",          // ← 合同专用：条款号
    "is_cross_page": false,       // ← 合同专用：是否跨页
    "cross_page_range": null      // 跨页时写 "12-13"
  }
}
```

**为什么这三样特别重要？**
- 律师审合同：问的就是"第 8.3 条怎么约定的"，**必须能按条款号直接搜**
- 跨页条款：PDF 里一条长条款经常跨两页，不标记 `is_cross_page` 的话，切片会把一条完整条款切成两半，语义断裂

---

### 📊 财报类 PDF 范例（金融/投研场景）

> **必须绑定上下文：明确数字的出处表名、对应指标及其核算年份。**

```json
// 财报类 PDF 的一个切片 Chunk 示例
{
  "chunk_text": "2024 年主营业务收入 125.6 亿元，同比增长 18.3%",
  "metadata": {
    "page": 34,
    "table_id": "表 3-2 合并利润表",   // ← 财报专用：表名/表编号
    "metric_name": "主营业务收入",      // ← 财报专用：指标名
    "year": 2024,                     // ← 财报专用：核算年份
    "currency": "CNY",
    "comparison_yoy": "+18.3%"
  }
}
```

**为什么这三样特别重要？**
- 财报里**表格多、数字密**，比如"收入 125.6 亿"——你不说年份，不说哪张表的，鬼知道是哪一年、哪个口径
- 面试官考 PDF 处理，**财报和合同是两个绕不开的场景**，你答到"按条款号标记"和"表名+年份绑定数字"这两个点，基本就满分了

---

> **一句话记忆：** Metadata 是 RAG 的"身份证"——**页码+章节**管定位，**表头+脚注**管语义正确，**合同按条款、财报按表名+年份**做场景化增强。
