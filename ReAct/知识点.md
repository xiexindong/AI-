# ReAct 知识点

## 一、一句话理解

ReAct = **Re**asoning(推理) + **Act**ing(行动),让大模型「边想边干」:先思考一步,再执行一步动作,看到结果后继续思考下一步,循环往复直到完成任务。

---

## 二、为什么需要 ReAct

### 普通 LLM 调用的局限

```
用户提问 → LLM 直接回答 → 结束
```

问题:
1. **知识有截止日期**:模型不知道今天天气、最新股价。
2. **不会算复杂计算**:大模型本质是预测下一个 token,做精确数学题容易翻车。
3. **不能主动调外部资源**:无法查数据库、发邮件、调 API。
4. **容易幻觉**:没有事实约束,模型可能瞎编。

### ReAct 的解决思路

把"思考"和"行动"分开,让模型:
- 每步先**想**(Thought)清楚下一步干什么
- 再**做**(Action)调一个真实工具拿事实
- 看**结果**(Observation)再决定下一步

---

## 三、核心四元素

| 字段 | 含义 | 类比 |
|---|---|---|
| **Thought** | 模型内心推理过程 | 人脑子里盘算 |
| **Action** | 调用什么工具/函数 | 人伸手去拿工具 |
| **Action Input** | 传给工具的参数 | 工具的输入 |
| **Observation** | 工具返回的结果 | 工具的反馈 |

最后一步用 `Answer` 或 `finish` 标记任务结束。

---

## 四、工作流程图

```
用户任务
   │
   ▼
┌─────────────────────────┐
│  ① Thought (LLM 推理)   │ ◄────┐
│  "我需要先查 X"          │      │
└─────────────────────────┘      │
   │                             │
   ▼                             │
┌─────────────────────────┐      │
│  ② Action (选工具+参数)  │      │
│  search("X")             │      │
└─────────────────────────┘      │
   │                             │
   ▼                             │
┌─────────────────────────┐      │
│  ③ Observation (工具返回) │      │
│  "X 的结果是 Y"          │ ─────┘
└─────────────────────────┘   循环
   │
   ▼  (Thought 判断足够了)
┌─────────────────────────┐
│  ④ Answer (最终答案)     │
└─────────────────────────┘
```

## 五、经典示例(伪输出)

任务:**上海今天需要带伞吗?**

```
Thought 1: 我需要先查上海今天的天气
Action 1: search_weather
Action Input 1: {"city": "上海"}
Observation 1: 上海今天 32℃,晴天,降水概率 5%

Thought 2: 降水概率只有 5%,晴天,不需要带伞
Action 2: finish
Action Input 2: {"answer": "不用带伞,上海今天是晴天"}

Answer: 不用带伞,上海今天是晴天
```

## 六、关键设计点

### 1. Prompt 模板
ReAct 通过约定一个固定格式(Thought/Action/Observation)的 prompt,让模型按格式输出,解析器再抽取出 Action 字段去调工具。

### 2. 循环结构
不是一次调用就完事,是 `while` 循环,直到模型输出 `finish` 类 Action 才终止。

### 3. 可解释性
每步 Thought 都暴露出来,容易调试为什么模型走错路。

### 4. 工具调用基础
ReAct 的 Action 这一步,后来演进成了 OpenAI 的 **Function Calling** 协议——本质一样,只是把"用什么格式告诉模型有工具可用"标准化了。

## 七、在 AI Agent 体系中的位置

```
┌─────────────────────────────────┐
│         AI Agent 架构            │
├─────────────────────────────────┤
│  用户任务                        │
│     │                           │
│     ▼                           │
│  ┌──────────────┐               │
│  │  Agent 大脑   │ ← ReAct 就    │
│  │  (调度循环)   │   是这个大脑  │
│  └──────────────┘               │
│     │                           │
│     ▼                           │
│  ┌──────────────┐               │
│  │  工具集合      │ ← 搜索/计算/  │
│  │  (Tools)      │   数据库/API │
│  └──────────────┘               │
│     │                           │
│     ▼                           │
│  最终答案                        │
└─────────────────────────────────┘
```

- LangChain 的 `AgentExecutor`、AutoGPT、BabyAGI 都基于这个循环。
- ReAct 是现代 Agent 调度逻辑的**基础原型**。

## 八、与其他范式对比

| 范式 | 怎么干 | 缺点 |
|---|---|---|
| 纯 Prompt | 一次性问一次答 | 不能调工具,易幻觉 |
| **ReAct** | 思考-行动-观察循环 | 步骤多时容易跑偏 |
| Function Calling | 协议化的 Action | 本质同 ReAct,只是标准化 |
| Plan-and-Execute | 先规划全流程再执行 | 灵活度低,遇到意外难调整 |

---

## 九、面试要点(背这段)

> **ReAct** 是一种让大模型通过 **"Reasoning 推理 + Acting 行动"** 交替循环来解决复杂任务的范式。模型每一步先输出思考过程(Thought),再决定调用哪个工具(Action),拿到工具返回结果(Observation)后继续推理,直到能给出最终答案。它的价值在于:
>
> 1. **可解释**:每步思考都可见,便于调试;
> 2. **可调工具**:突破 LLM 知识截止、计算能力短板;
> 3. **抗幻觉**:Observation 作为事实约束,模型基于真实返回继续推理。
>
> 它是现代 AI Agent 调度逻辑的基础原型,LangChain Agent、Function Calling 都是在其思路上演进。

## 十、常见追问

**Q1:ReAct 和 Function Calling 啥关系?**
Function Calling 是 ReAct 中 Action 步骤的标准化协议版本。ReAct 靠 prompt 约定格式,Function Calling 由模型原生支持工具调用,更稳定。

**Q2:ReAct 的最大问题是什么?**
- 步骤多时容易"思考跑偏",最后偏离目标;
- 每一轮都要调一次 LLM,token 消耗大;
- 依赖工具返回质量,工具出错模型也跟着错。

**Q3:如何终止循环?**
通常约定一个特殊 Action(如 `finish` 或 `Final Answer`),解析器看到就退出循环;也可以加最大轮次兜底。
