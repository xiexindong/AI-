# Skill 路由运行原理：从用户说话到调对 Skill，全流程怎么串起来？

## 一、通俗类比（先建立直觉）

### 1.1 把整个 Skill 路由系统想象成：**一个"豪华大饭店"的点菜系统**

| 饭店里的角色 | 对应 Agent 里的组件 | 干什么活 |
|------------|-------------------|---------|
| 🗒️ 菜库（后厨菜谱大全） | Skill 库（几百上千个 Skill） | 全量能力都在这，**但没人能全背下来** |
| 🏷️ 每道菜的菜名+描述（菜单上印的） | Skill 的 Name + Description（±负面描述） | 路由的"检索摘要"，**描述质量直接决定能不能被点到**（策略01、策略03） |
| 👷 迎宾小哥（快速推荐） | 轻量级召回层（Embedding / 关键词） | 客人只说"想吃甜口的"，小哥快速从 500 道菜里挑 10 道最像的端过来（策略04） |
| 🧑‍🍳 大堂经理（最终拍板） | LLM 精排层（大模型） | 拿着这 10 道菜的菜单，结合客人的原话、忌口、口味，**强推理**选最对的那道（策略04） |
| 🧭 饭店整体规矩（怎么做生意） | Agent 底座的上下文工程 | 整个流程能运转的基础，比如"客人有忌口要先问""先看菜单再点菜"等（支柱①） |

---

## 二、完整运行流程（6 步走）

> 以用户说 **"帮我做一份融资路演用的 PPT，20 页左右"** 为例，一步步跑一遍。

```
Step 1  用户输入原始请求
   │
   ▼
Step 2  【底座层】Agent 底座处理：清洗意图 + 拼 Prompt 模板
   │   （支柱①：贴合业务的 Agent 底座）
   ▼
Step 3  【召回层】向量化/关键词，从全量 Skill 库快速捞 Top 10
   │   （策略04 · 召回阶段）
   ▼
Step 4  【精排层】把 Top 10 + 正面描述 + 负面描述塞给 LLM
   │   （策略01 写"何时用" + 策略03 写"何时不用" + 策略04 · 精排阶段）
   ▼
Step 5  【决策层】LLM 输出结构化结果：选哪个 Skill + 传什么参数
   │
   ▼
Step 6  【执行层】真正调用 Skill → 返回结果给用户
   │
   └─→ 如果出错/被负面描述拦截，可回到 Step 4 重选
```

下面每一步展开讲，**特别标注"哪条策略在这一步发力"**。

---

## 三、每一步详解（附：哪个策略在此生效）

### Step 1：用户输入原始请求

用户说：**"帮我做一份融资路演用的 PPT，20 页左右"**

- 这一步还没涉及 Skill，就是原始自然语言文本
- 关键：**用户说得越具体，后面命中越准**（比如不说"做个文件"，说"融资路演 PPT"，对后面的语义匹配帮助巨大）

---

### Step 2：【底座层】Agent 底座处理（支柱①）

> ✅ **三大支柱之① —— 贴合业务的 Agent 底座，在这一步发挥作用。**

#### 2.1 先用饭店类比理解"底座"是啥

回到前面那个饭店类比——**底座就是"饭店的整体规矩和运营手册"**：

- 客人进门，迎宾小哥不是直接喊"想吃什么"，而是先**问几位、有没有忌口、是不是包间**——这就是底座的活
- 上菜之前服务员要**核对一下点菜单**，确认没点重复的菜——这也是底座的活
- 整个流程"先点菜→后上菜→结账走人"的顺序不能乱——这还是底座定的

**对应到 Agent：** 底座不是某个具体的"模型"，而是**一套程序代码 + Prompt 模板 + 规则**，负责把用户原话"喂"给后面 LLM 之前，先做一遍预处理和约束。

#### 2.2 底座干的 7 件事（不止原文 3 件）

| # | 动作 | 通俗讲 | 例子（用户说："帮我整个融资路演用的 PPT，20 页左右"） |
|---|------|-------|--------------------------------------------------|
| ① | **意图清洗** | 把口语废话词去掉，留下核心动作 | "帮我整个...左右" 这种废话去掉 → 规整成"生成融资路演 PPT，页数 20" |
| ② | **关键信息抽取** | 从原话里抽出来结构化字段（参数） | 抽出 `{topic: "融资路演", product: "PPT", pages: 20}`，这些后面要传给 Skill 当参数 |
| ③ | **多轮上下文管理** | 看看之前对话说过啥，要带上的就带上 | 如果上一轮用户说过"我们公司是做 AI 的"，底座要把"公司=AI 公司"塞进 Prompt，让 LLM 选 Skill 时考虑这个背景 |
| ④ | **路由策略选择** | 判断要不要走"召回+精排"，还是直接调 | Skill 只有 5 个时，不用召回，直接全塞给 LLM 选；Skill 有 500 个时，才走召回+精排 |
| ⑤ | **Prompt 模板拼装** | 按固定模板把"规则+用户请求+候选 Skill"拼好 | 把"系统规则""用户原话""Top 10 候选 Skill"按顺序拼成一个大字符串，喂给 LLM |
| ⑥ | **输出格式约束** | 强制 LLM 按规定格式回话 | 在 Prompt 里写死"必须输出 JSON：`{selected, reason, params}`"，不然 LLM 会跟你聊天 |
| ⑦ | **安全/合规校验** | 防注入、过滤敏感词 | 用户输入里如果藏了"忽略前面的指令"（Prompt 注入攻击），底座先拦下来 |

#### 2.3 拼出来的 Prompt 模板长啥样（直观感受）

底座拼完之后，真正传给 LLM 精排的 Prompt 大概长这样：

```text
【系统规则 · 由底座写死】
1. 你必须从下面的候选 Skill 列表里选一个，不能编不存在的 Skill。
2. 必须严格遵守每个 Skill 的 negative_description（禁忌描述）。
3. 输出必须严格按 JSON 格式：{"selected": "...", "reason": "...", "params": {...}}

【用户原话】
帮我整个融资路演用的 PPT，20 页左右

【底座清洗后的意图】
意图：生成 PPT
关键信息：{topic: "融资路演", product: "PPT", pages: 20}

【多轮上下文（来自之前对话）】
- 用户公司：AI 创业公司
- 用户偏好：简洁风格

【候选 Skill 列表 Top 10】
1. generate-ppt
   description: ...
   negative_description: ...
2. generate-document
   description: ...
   negative_description: ...
... (剩下 8 个)
```

> 注意 **【系统规则】【多轮上下文】【清洗后的意图】** 这三块——都是**底座**自己加进去的，LLM 本身不会自己想出来要做这些。底座不强，LLM 就在"真空中瞎选"。

#### 2.4 底座写得差的后果

| 底座没做的事 | 后果 |
|------------|------|
| 不做意图清洗 | 用户口语废话词干扰向量匹配，召回准确率掉 |
| 不抽参数 | LLM 选对 Skill 但参数没准备好，Skill 执行时还得再问用户一遍 |
| 不带上下文 | 多轮场景下，LLM 不知道之前聊过啥，每次都像第一次见面 |
| 不选路由策略 | Skill 只有 5 个也走全套召回+精排，又慢又费钱 |
| 不约束输出格式 | LLM 用自然语言回话，程序解析不出来，没法调 Skill |
| 不做安全校验 | Prompt 注入攻击一发入魂，Agent 直接被人操控 |

**一句话记忆：** 底座是"幕后导演"——不亲自选 Skill，但**选 Skill 这场戏能不能演好，全看它前期准备得怎么样**。LLM 是演员，底座是导演。

---

### Step 3：【召回层】轻量级召回 Top 10（策略04 · 前半段）

> ✅ **策略 04（召回+重排）的前半段 —— 召回阶段，在这一步发力。**

```
全量 Skill 库（500 个）
    │
    │  1. 把用户请求 → Embedding 成向量（比如 1536 维）
    │  2. 把每个 Skill 的 Name + Description → 也提前存成向量
    │  3. 计算余弦相似度，取 Top 10（或 Top 20）
    │  （也可以混合关键词匹配，比如用户说了"PPT"，把含"PPT"关键词的 Skill 加分）
    ▼
候选 Top 10（大概是：生成PPT、生成文档、生成海报、写演讲稿、数据可视化...）
```

**这一步的特点：**
- ⚡ 极快（毫秒级，向量数据库现成方案）
- 💰 极便宜（不调用大模型，只跑 Embedding 小模型）
- 🎯 **目标是"别漏掉"**（召回率优先，准确率其次，宁可错捞几个候选，别把正确的 Skill 漏了）
- ❌ **不要求精确**（捞出来的 Top 10 里可能有"生成文档"这种干扰项，没关系，下一轮精排会筛）

---

### Step 4：【精排层】LLM 精排（策略 01 + 策略 03 + 策略04 后半段）

> ✅ **三条策略在这一步一起发功：**
> - 策略 01：描述里写了"当用户需要融资路演时使用" → 让 PPT Skill 的匹配度暴涨
> - 策略 03：负面描述帮你排除干扰项（比如"生成文档"的负面描述里写了"不要在融资路演场景下用"）
> - 策略 04：精排阶段 —— 候选池已经从 500 缩到 10，LLM 能集中注意力看

这一步传给 LLM 的 Prompt 大概长这样（伪代码）：

```text
【系统提示】
你是一个 Skill 路由助手，必须严格从下面的候选 Skill 中选最匹配的一个。
选的时候既要参考 description，也要严格遵守 negative_description。
输出 JSON：{"selected": "...", "reason": "..."}

【用户请求】
帮我做一份融资路演用的 PPT，20 页左右

【候选 Skill 列表】
1. name: generate-ppt
   description: "当用户需要制作汇报材料、融资路演或季度总结时使用。"
   negative_description: "不要用来生成纯文本 Word 文档。"

2. name: generate-document
   description: "当用户需要写 Word 文档、写报告、写合同文本时使用。"
   negative_description: "不要在融资路演、季度总结等需要 PPT 场景使用。"

3. name: generate-poster
   ...（剩下 8 个）
```

LLM 拿着这个 Prompt 一推理：**候选 2 的 negative_description 明确说了"融资路演别用我"，候选 1 正好对上"融资路演"场景** → 稳选 generate-ppt。

---

### Step 5：【决策层】LLM 输出结构化结果

LLM 返回：

```json
{
  "selected": "generate-ppt",
  "reason": "用户明确提了"融资路演"且要做"PPT"，完全匹配 generate-ppt 的 description；其他如 generate-document 被负面描述排除。",
  "params": {
    "topic": "融资路演",
    "pages": 20
  }
}
```

**关键点：一定要结构化输出（JSON Schema）**
- 不然 LLM 跟你瞎聊天，程序没法解析下一步调哪个 Skill
- 如果这一步 LLM 选了被负面描述禁用的 Skill，底座可以做规则校验再拦一次（纠错机制）

---

### Step 6：【执行层】真正调用 Skill

程序解析 JSON → 找到 `generate-ppt` 这个 Skill → 把 `{topic, pages}` 作为参数传进去 → Skill 执行 → 把 PPT 文件路径返回给用户。

**出错兜底：** 如果 Skill 执行失败（比如参数不对），可以把错误信息塞回 Step 4，让 LLM 重选一次或修正参数。

## 四、一张表看懂：每条策略对应流程中的位置

| 流程步骤 | 什么在起作用 | 做了什么 | 对应哪个策略 / 支柱 |
|---------|------------|---------|-------------------|
| Step 2 底座处理 | Agent 底座 | 清洗意图、拼 Prompt 模板、定规则 | 支柱① 贴合业务的 Agent 底座 |
| Step 3 召回 Top 10 | 向量库 / 关键词 | 从 500 → 10，快速缩小池子 | 策略 04（召回阶段） |
| Step 4 LLM 精排 | 正面描述 | "融资路演"直接匹配到 PPT Skill | 策略 01（写何时用） |
| Step 4 LLM 精排 | 负面描述 | 把 generate-document 排除掉 | 策略 03（边界防御） |
| Step 4 LLM 精排 | LLM 强推理 | 10 选 1，深度语义判断 | 策略 04（精排阶段） |
| Step 5 结构化输出 | JSON Schema + 底座校验 | 防 LLM 瞎输出 | 支柱① 底座 |

## 五、伪代码：50 行看懂怎么串联

```python
# ====== 主流程函数 ======
def skill_router(user_input: str):
    # === Step 1 + 2：底座处理 ===
    cleaned_intent = agent_base.clean_intent(user_input)
    key_info = agent_base.extract_info(user_input)  # {topic: "融资路演", page: 20}

    # === Step 3：轻量级召回（策略04 前半段）===
    user_vector = embedding_model.encode(cleaned_intent)
    top_10_skills = vector_db.search(user_vector, top_k=10)  # 从 500 个 Skill 里捞 10 个

    # === Step 4：LLM 精排（策略01 + 策略03 + 策略04后半段）===
    routing_prompt = build_routing_prompt(
        user_input=user_input,
        candidate_skills=top_10_skills  # 每个 Skill 都带 name + description + negative_description
    )
    llm_result = llm.call(routing_prompt, response_format=JSON_SCHEMA)
    # llm_result 形如：{"selected": "generate-ppt", "params": {...}}

    # === Step 5：底座规则校验（纠错） ===
    selected_skill = find_skill_by_name(llm_result["selected"])
    if not check_negative_description(selected_skill, user_input):
        # 居然违反了负面描述？拦下来重选
        return skill_router(user_input + "注意，不要选违反负面描述的 Skill！")

    # === Step 6：执行 Skill ===
    result = selected_skill.execute(params=llm_result["params"])
    return result
```

> **一句话串起来：** 底座打底 → 轻召回缩池子 → 精排看正反面描述选 → 校验不通过就重来 → 最终执行。

## 六、为什么命中率能上去？—— 每一层都在过滤

```
500 个 Skill
   ↓  召回层（策略04）：错捞可以，别漏 → 剩 10 个
   ↓  策略01（正面描述）：找最像的 → 剩 2-3 个
   ↓  策略03（负面描述）：排除边界外的 → 剩 1 个
   ↓  底座校验：防 LLM 犯傻 → 最终 1 个（大概率是对的）
```

**层层过滤，层层加保险**——这就是为什么命中率从 60% 能做到 99% 的根本原因：不是靠某一条策略，是靠多层串联。
